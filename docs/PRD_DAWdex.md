## 一、产品定义

### 一句话描述

> DAWdex 是一个由弹幕驱动的 AI 虚拟乐队：制作人 Agent 将观众的日常语言编译成专业音乐任务，并带领虚拟乐手在统一乐理框架中逐轨完成一首作品。

### 产品本质

DAWdex 不是传统 DAW 的聊天遥控器，也不是 Prompt-to-Audio 生成器。它是一种让音乐小白也能参与编曲的互动体验：

1. 观众用自然语言表达感受；
2. 制作人 Agent 判断哪些意见值得采用；
3. 音乐意图编译器把模糊语言变成结构化音乐参数；
4. 不同虚拟角色领取职责明确的任务；
5. 系统检索和修改高质量 MIDI；
6. 轨道在音乐持续循环时逐步加入；
7. 用户听见自己的意见真正改变作品。

### 核心创新组合

单独的弹幕、角色人设、MIDI 检索和 DAW 都不是产品壁垒。DAWdex 的黑客松创意来自它们的组合：

- 评论从“作品完成后的反馈”变成“作品生成中的控制信号”；
- 模型输出从一段不可编辑音频变成角色化、可解释的编曲任务；
- 音乐不是一次性出现，而是在循环中逐轨生长；
- 观众能够看到“人话如何被编译成音乐”，并立即听见结果。

## 二、目标用户与使用场景

### 核心用户

核心用户具备以下特征：

- 不理解 BPM、调性、Voicing、Groove 等专业术语；
- 对音乐、游戏、直播、二创或虚拟角色有兴趣；
- 希望自己的意见被作品采纳；
- 不愿面对传统 DAW 的复杂界面；
- 更看重参与感和即时反馈，而不是精细工程控制。

### 次要用户

专业或半专业音乐人可以把 DAWdex 作为灵感入口，但不是本次 Demo 的主要叙事对象。专业模式、完整工程编辑和高级导出属于后续能力。

### 首个场景

一段基础 Groove 在循环播放。观众发送：

> “再炸一点，像游戏最终 Boss 出场。”

制作人选择这条意见，总编曲师保持 128 BPM 与 A 小调，鼓手加入四拍底鼓和密集踩镲，贝斯手增加八分音符推进，键盘手保持和弦但提高音区。每名虚拟乐手在对应轨道进入时开始演奏。

## 三、核心能力：音乐意图编译器

### 定义

音乐意图编译器不是一段隐藏的系统 Prompt，而是一条可观察、可验证的数据管线：

```text
自然语言
→ 纠错与去重
→ 意见聚类
→ 制作人评分与裁决
→ 全局 Music Brief
→ 角色任务
→ 可执行音乐操作
→ 质量校验
```

### 示例

输入：

> “别那么软，想要快打 Boss 的感觉，但钢琴别乱改。”

输出：

```json
{
  "audienceIntent": {
    "summary": "提高紧张感和推进感",
    "energyChange": 2,
    "tensionChange": 2
  },
  "globalConstraints": {
    "bpm": 128,
    "key": "A minor",
    "bars": 4,
    "preserve": ["keyboard-chords"]
  },
  "roleTasks": [
    {
      "role": "drummer",
      "decision": "加入四拍底鼓和十六分踩镲",
      "operation": "add-drum-pattern"
    },
    {
      "role": "bassist",
      "decision": "使用八分音符根音推进",
      "operation": "add-bass-pattern"
    },
    {
      "role": "keyboardist",
      "decision": "保留和弦进行，只调整音区",
      "operation": "transform-voicing"
    }
  ]
}
```

### 可见性原则

- 用户首先看到角色对话，而不是完整 JSON；
- 专业术语附带通俗解释；
- 可折叠区域展示本次结构化编曲指令；
- 角色工作回执必须从实际指令生成；
- 同一份指令同时驱动 UI 和 DAW，避免“说一套、做一套”。

## 四、角色系统

| 角色 | 决策范围 | Demo 中的表现 |
|---|---|---|
| 制作人 Agent | 筛选弹幕、确定意图、批准结果 | 主持乐队会议 |
| 总编曲师 Agent | BPM、调性、和弦、长度、角色分工 | 发布 Music Brief |
| 鼓手 Agent | Groove、底鼓、军鼓、踩镲、密度 | 鼓轨进入时开始动画 |
| 贝斯手 Agent | 根音、节奏、音域、推进方式 | 贝斯轨进入时开始动画 |
| 键盘手 Agent | 和弦、Voicing、节奏与音区 | 键盘轨进入时开始动画 |
| 主奏 Agent | Motif、旋律方向和小节变体 | Lead 轨进入时开始动画 |
| 混音师 Agent | 音量、声像和基础效果 | MVP 使用规则引擎代替 |

### 多 Agent 表述

- 如果后台一次模型调用生成所有角色任务，称为“多角色 Agent 编排”；
- 如果每个角色拥有独立上下文并分别调用模型，再由制作人合并，才称为“多 Agent 协作”；
- 本次 Demo 优先稳定性，可以一次生成整体蓝图，再在 UI 中按角色逐步执行；
- 不展示模型私有思维链，只展示可验证的决策摘要和工作回执。

## 五、核心体验流程

### Flow 1：进入舞台

1. 打开 DAWdex；
2. openDAW 加载基础工程或安全预设；
3. 全屏弹幕遮罩、角色区域和 Agent 面板出现；
4. 基础 Loop 开始播放。

### Flow 2：弹幕进入

1. 用户发送弹幕；
2. 原文立即从屏幕飘过；
3. 系统纠正常见转写错误和乱码；
4. 相似意见聚类；
5. 制作人按相关性、共识、可实现性、新颖性和连续性评分；
6. UI 显示被采用的意见。

AI 生成的活跃气氛弹幕必须标记为“AI 乐迷”或“虚拟观众”，不能冒充真人。

### Flow 3：编译与角色交接

1. 制作人说明选择理由；
2. 总编曲师发布统一 Music Brief；
3. 各乐手领取自己的结构化任务；
4. UI 用专业术语加通俗解释展示工作回执；
5. 对应角色进入“准备演奏”状态。

### Flow 4：素材与变体

1. 根据风格、角色、调性、拍号、能量和密度检索 MIDI；
2. 将素材移调至工程调性；
3. 适配工程 BPM 与固定小节长度；
4. 调整音域、力度、节奏或结尾走向；
5. 与已有轨道做冲突检查；
6. 不合格时重试或回退到安全版本。

### Flow 5：逐轨加入

1. 已生成轨道无限循环；
2. 新轨完成后等待下一循环边界；
3. 轨道和对应虚拟乐手同时进入；
4. 用户能够立刻听到作品增加了一层；
5. 用户可以选择保留、重做、换乐器、增强或减弱。

## 六、功能需求

### FR-01：全屏弹幕层

- 弹幕覆盖整个应用画面，位于最前层；
- 不阻断必要的输入、批准和播放操作；
- 支持多轨道、速度、透明度和自动销毁；
- 区分真人弹幕、系统状态和 AI 乐迷；
- 长文本截断，危险内容过滤。

### FR-02：制作人裁决

- 接收一条或多条弹幕；
- 纠错、去重和聚类；
- 输出被采用意见、简短理由和置信度；
- 无有效输入时可以使用预设或明确标记的 AI 乐迷建议；
- 冲突意见由制作人依据当前工程状态裁决。

### FR-03：音乐意图编译

- 输出必须通过 Schema；
- 包含意图、全局约束、角色任务和可执行操作；
- 硬性参数使用程序校验；
- 模型不得绕过允许的动作集合；
- UI 文案与执行动作共享同一数据源。

### FR-04：角色对话

- 不同角色具有固定职责、名称、视觉和语气；
- 每条工作回执说明“将做什么”和“听起来会怎样”；
- 点击角色消息可定位对应轨道或任务；
- 角色状态至少包含等待、思考、准备、演奏和失败。

### FR-05：MIDI 素材库

- 素材具有来源、许可证和可分发状态；
- 索引风格、角色、BPM、调性、拍号、长度、能量和密度；
- 检索结果不得直接不加判断地复制；
- 支持受约束的移调、裁剪、量化、力度和音符变体；
- 记录素材 ID 与变换操作，便于复现。

### FR-06：音乐托底

硬性规则必须由代码保证：

- 工程只有一个权威 BPM、调性、拍号和循环长度；
- MVP Clip 统一为 4 或 8 小节；
- MIDI 音符位于对应乐器合理音域；
- 新轨在量化后的循环边界加入；
- 限制峰值、默认音量和同时发声轨道数；
- 校验失败时不进入播放，自动使用安全版本。

### FR-07：openDAW 执行

- 音乐操作保留为可编辑 MIDI；
- 一次计划作为一个 Undo 单元；
- 执行前校验动作；
- 执行后确认轨道和 Region 已创建；
- 失败不能破坏正在播放的已有 Loop。

### FR-08：Agent Provider

- 当前支持 OpenAI 原生环境变量；
- 目标支持 OpenAI、千问和自定义 OpenAI-compatible API；
- API Key 只保存在本地可信进程；
- Provider 必须声明 Responses 或 Chat Completions 协议；
- Codex CLI、Claude Code 或 Qwen Code 属于可选 Runtime，不是 Demo 前置条件。

### FR-09：交互控制

每轨完成后提供：

- 保留；
- 更有力量；
- 更轻松；
- 换一种乐器；
- 重新生成；
- 撤销上一次 DAWdex 修改。

## 七、MVP 范围

### P0：必须真实可用

- 基于 openDAW 的可运行页面；
- 全屏弹幕输入与移动；
- 制作人接收一条观众意见；
- 外行语言转换为结构化 Music Brief；
- 至少三个角色工作回执；
- 至少三条可编辑 MIDI 轨道；
- 轨道按统一 BPM、调性和长度生成；
- 已完成轨道持续循环；
- 新轨在明确的顺序中加入；
- 角色动画与轨道有声/无声状态一致；
- 模型失败时有本地回退；
- 一次 Undo；
- 预录演示视频作为现场回退。

### P1：主链稳定后

- MIDI 素材真实检索和变体；
- 多条弹幕聚类、评分和裁决；
- AI 乐迷；
- 用户对单一角色继续追问；
- 千问与自定义 API Provider；
- 成品 Blueprint 或 MIDI 导出。

### P2：比赛后

- 真正并行的多 Agent；
- Codex/Claude/Qwen CLI Runtime；
- 高级混音和母带；
- 音符级虚拟乐手动画；
- 完整歌曲结构和任意长度；
- 专业音乐人模式；
- Electron 安装包；
- 真实直播平台 API。

### 明确不做

- 从零训练音乐模型；
- 直接生成不可编辑的最终音频；
- 完整重做一套专业 DAW；
- VST Host；
- 未标记的虚假真人弹幕；
- 无限制让模型执行任意工程操作。

## 八、90 秒 Demo

```text
0–8 秒    一句话：用弹幕指挥 AI 虚拟乐队
8–18 秒   基础 Loop 播放，观众发送“像最终 Boss 一样炸”
18–30 秒  制作人采用意见，意图编译器生成专业 Music Brief
30–45 秒  总编曲师、鼓手、贝斯手、键盘手依次领取任务
45–68 秒  轨道在循环边界逐个加入，虚拟乐手开始演奏
68–80 秒  用户选择“再加一点推进感”，下一轨发生变化
80–90 秒  展示最终作品、结构化指令和一句核心结论
```

结尾：

> 观众说人话，AI 乐队把它变成真正可编辑的音乐。

## 九、成功指标

### 体验指标

- 观众在 10 秒内理解“我可以用弹幕影响音乐”；
- 观众能够指出自己的意见改变了哪一轨；
- 角色对话与听到的变化一致；
- 整个 90 秒 Demo 不需要解释传统 DAW 操作；
- 至少 3 名目标用户完成一次“输入—采用—听见变化”。

### 技术指标

- 固定 Demo 环境启动成功率 100%；
- Prompt 到第一条角色回执不超过 8 秒；
- 每个 MIDI 操作通过 Schema 和硬规则校验；
- 新轨在量化边界加入；
- 模型失败时 2 秒内进入本地回退；
- Demo 全程无爆音、无静音死锁、无工程损坏。

## 十、风险与响应

| 风险 | 响应 |
|---|---|
| 角色只是在说漂亮话 | 对话从执行 JSON 派生，同一数据驱动 DAW |
| 音乐雷同 | 扩充动作协议、增加素材检索、Seed、Motif 和变体 |
| 模型破坏乐理 | 代码执行 BPM、调性、长度、音域和边界硬规则 |
| 多 Agent 太慢 | 一次生成整体蓝图，UI 分阶段呈现 |
| 现场模型不可用 | 本地 Planner 和固定安全素材回退 |
| 弹幕过少 | 明确标记的 AI 乐迷或预设观众加入 |
| 弹幕过多或冲突 | 聚类、评分和制作人裁决 |
| 动画与声音穿帮 | 角色只按轨道是否发声切换演奏状态 |
| MIDI 素材授权不清 | 素材入库时记录许可证与可分发状态 |
| openDAW 集成不稳定 | 固定版本、固定工程、构建验证和预录视频 |

## 十一、当前实现与目标差距

当前原型已经完成 Prompt、项目快照、模型/本地计划、确认、写入 openDAW 和 Undo，但协议只有：

```text
set-tempo
create-instrument(bass | chords | pulse | lead)
```

当前 `compilePattern` 使用固定和弦进行和确定性音符算法，因此不同提示词仍会产生类似片段。下一阶段优先级不是更换更大的模型，而是：

1. 引入 `MusicBrief` 和 `RoleTask` Schema；
2. 增加 drums、groove、key、scale、motif、variation 和 seed；
3. 建立 MIDI 素材元数据与检索；
4. 让 openDAW 读取真实现有音符；
5. 加入循环边界调度和质量闸门。

## 十二、完成定义

本次黑客松 Demo 完成必须同时满足：

- [ ] 用户输入一句非专业弹幕；
- [ ] 制作人明确采用或拒绝；
- [ ] UI 展示结构化音乐意图；
- [ ] 至少三个角色给出与实际动作一致的工作回执；
- [ ] 至少三条 MIDI 轨道依次加入循环；
- [ ] 每名虚拟乐手的状态与对应轨道一致；
- [ ] 用户至少干预一次后续编曲；
- [ ] 最终作品可持续循环并可以撤销；
- [ ] 模型不可用时 Demo 仍能继续；
- [ ] 90 秒内完整讲清“弹幕如何变成音乐”。
