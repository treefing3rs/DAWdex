## 一、选择结论

### 主赛道：08｜干杯！创造属于你的 B 站新纪元

选择方向一“产品创意太牛 bilibili 了”。

DAWdex 的产品本体是面向音乐制作的 DAW Agent，而不是 B 站插件。它与 B
站赛道的连接点，是一个专门的 `Crowd Arrangement` 演示 Skill：

```text
弹幕 / 评论
→ 聚合为音乐意图
→ DAWdex 读取当前 Ableton 工程
→ 展示编曲计划与影响范围
→ 创作者确认
→ MCP 修改可编辑的轨道、Clip 与 MIDI
→ Before / After
```

这个选择同时满足两件事：

- 产品定位不被缩窄：主入口仍是音乐人直接用自然语言操控 DAW；
- 赛道回应足够具体：B 站特有的弹幕、评论和二创文化成为一次真实可见的创作输入。

赛道评审关注创新性、落地性、产品体验和扩展性。DAWdex 可分别用以下证据回应：

| 评审维度 | DAWdex 的证据 |
|---|---|
| AI 应用创新性 | 把弹幕从观看后的反馈，变成 DAW 中可执行、可审计的音乐修改 |
| 实现可落地性 | Codex → MCP → Ableton Live 真实链路已经完成初步验证 |
| 产品体验完成度 | Electron 中展示 Context、Plan、Approval、Tool Call 和 Before / After |
| 未来扩展性 | 同一套 DAW Agent 可服务 UP 主配乐、直播 BGM、鬼畜、音乐区与客户改稿 |

### 次赛道：05｜不做第一，做唯一

这个赛道没有指定技术平台门槛，且重视“痴迷 × 独特优势 × 真实需求”。
DAWdex 的优势不是“第一次有人做 AI 音乐”，而是团队同时具备：

- 对 AI 音乐不可控、难以局部修改问题的真实认识；
- 对 DAW 编曲工作流的理解；
- 已经把 Coding Agent、MCP 和 Ableton Live 跑通的实践；
- 把复杂 Agent 能力做成可理解音乐 UX 的设计能力。

该赛道能否形成有竞争力的提交，取决于 7 月 25 日前是否获得真实用户反馈。
不能用团队自己的推测代替音乐人、UP 主或制作人的原话。

## 二、主赛道提交问题与正式回答

### 赛道问题

> 你的产品最大的亮点是什么？它如何服务 B 站 UP 主、用户和社区？
> 如果参与直播，请说明直播整活策划。

### 可直接使用的提交回答

DAWdex 是一个为音乐制作定制的 Codex-like 桌面 Agent。它最大的亮点不是再用
Prompt 生成一段不可编辑的成品音频，而是读取真实 Ableton Live 工程，把创作者
或观众的自然语言意见变成可解释的编曲计划，再通过 MCP 直接修改轨道、Clip、
MIDI 与音色，并展示执行记录和 Before / After。结果仍然留在 DAW 中，创作者可以
继续编辑。

面向 B 站，我们把弹幕实时编曲做成 DAWdex 的一个 `Crowd Arrangement` Skill。
例如观众发送“副歌再燃一点”“别太满”“让吉他回应”，系统先聚合意见，再结合当前
工程判断小节范围、能量、密度和乐器职责。创作者看到计划并确认后，Ableton 中会
出现真实、可编辑的编曲变化。

它为三类参与者创造价值：

- UP 主可以把模糊的弹幕和评论快速转成配乐、翻唱、鬼畜、直播 BGM 的可编辑修改，
  不必推倒重做；
- 用户的弹幕不再只是作品完成后的反馈，而能以受控方式参与下一版作品；
- 社区可以形成“评论驱动创作”的互动与二创流程，同时保留创作者的最终决定权。

DAWdex 不是一个 B 站专用工具。B 站场景是最有展示力的输入方式之一，它证明同一个
DAW Agent 既能听懂单个音乐人的制作要求，也能把群体反馈变成安全、透明的音乐操作。

### 若参加直播方向，可使用的策划

直播主题：`让弹幕成为今晚这段音乐的制作团队`。

1. 主播先播放 8 小节原始循环；
2. 观众只使用白名单意见投票，例如“更燃”“空一点”“吉他回应”；
3. DAWdex 每 20 秒聚合一次弹幕，并显示理解、目标小节和计划；
4. 主播点击 Apply，Ableton 现场修改；
5. 播放 Before / After，由观众投票保留或再改一轮；
6. 展示 Action Log，说明哪些意见被采用、哪些因冲突或安全限制未执行。

直播安全边界：

- 不让单条弹幕直接调用 MCP；
- 只开放预定义的可逆音乐动作；
- 删除、覆盖、保存工程等重要操作不开放；
- 每轮都由主播确认；
- 使用固定 Demo 工程和一键重置。

## 三、次赛道提交回答草案

### 问题 1：为什么是你们做这个？

我们三个人的交集正好落在 DAWdex 上：一位成员长期关注产品表达、视觉设计和内容
传播；一位成员负责 Agent 框架，并已经亲手完成 Coding Agent 通过 MCP 操作
Ableton Live 的初步验证；另一位技术成员负责把 Electron、IPC、状态、测试和打包
连接成稳定产品。我们不是先有一个 AI 技术再寻找音乐场景，而是从真实的 DAW
修改流程出发：音乐人最痛苦的往往不是“生成第一版”，而是把“副歌不够炸、这里
太满、保留主旋律”稳定地变成可编辑操作。这既是我们的兴趣和实践交集，也是
DAWdex 只有这支团队能在本次比赛中快速做出来的原因。

### 问题 2：真实用户与反馈

截至 2026-07-23，团队已完成技术链路初步验证，但不能把内部验证写成外部用户反馈。
提交前至少邀请以下三类用户各一位完成 10 分钟测试：

| 用户 | 核心任务 | 必问问题 |
|---|---|---|
| Ableton / DAW 用户 | 用自然语言修改一段现有工程 | 哪一步比手工操作更有价值？哪一步让你不放心？ |
| B 站音乐或视频创作者 | 把三条评论变成配乐修改 | 这个流程是否真的能减少改稿时间？ |
| 编曲人 / 音乐制作学习者 | 查看计划并判断是否愿意 Apply | 计划是否使用了你能理解的音乐语言？ |

提交材料必须补上：

- 用户身份的匿名描述；
- 实际使用了哪个版本；
- 一句原话；
- 团队因此修改了什么；
- 若用户不愿使用，也如实记录原因。

## 四、主题建议

暂定主题 `E｜Reverse 反转`：

- 传统 AI 音乐：Prompt → 扁平成品；DAWdex：意图 → 可编辑工程；
- 传统 DAW：人逐项操作；DAWdex：人做审美决策，Agent 规划并执行；
- 传统弹幕：作品后的反馈；DAWdex Demo：弹幕成为下一次编曲的输入。

赛道表对主题只给出了视频文件名，没有文字说明。最终提交前必须看完官方主题视频，
确认这个解释与官方语义一致；在此之前不要把主题解读写成已确认规则。

## 五、90 秒赛道 Demo

```text
0–8 秒    一句话：为音乐制作定制的 Codex
```

评委误以为 DAWdex 只是一个弹幕触发器。
