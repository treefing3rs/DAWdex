# DAWdex 参赛赛道策略与提交回答

> 本文依据 0.3.0 / PR #11 与完整歌曲正式方向整理。赛道规则可能变化，
> 最终报名时必须再次核对主办方页面、工具使用条件和提交字段。

## 一、项目与主题

### 主题建议：Reverse / 反转

DAWdex 反转了评论、AI 音乐和 DAW 的关系：

1. 评论不再发生在作品完成之后，而是成为编曲入口；
2. AI 不直接交付一段成品音频，而是组织虚拟乐队完成可编辑音乐；
3. 用户不需要学习 DAW，系统把外行语言编译为专业操作；
4. “加载过程”不再隐藏，而是成为角色化的音乐制作表演。

主题句：

> DAWdex reverses the role of comments: audience reactions are no longer feedback after creation; they become the interface of creation itself.

## 三、主赛道提交回答

### 产品最大亮点是什么？

> DAWdex 把 B 站最有特色的弹幕，从观看后的反馈变成音乐创作中的控制层。观众只需要发送“再炸一点”“像最终 Boss 出场”“钢琴不要这么温柔”这样的日常语言，制作人 Agent 就会把它转换成 Creative Brief，从真实 MIDI 资料中检索精确素材，并提出可审批的编排、音色和 DAW 操作。虚拟鼓手、贝斯手和键盘手只在轨道真实发声后演奏，观众能看见并听见自己的意见如何改变工程。

### 如何服务 UP 主、用户和社区？

> 对 UP 主，它提供一种可以直接用于直播、音乐区、鬼畜区和虚拟主播内容的新互动形式；对观众，弹幕不再只是情绪表达，而是可以影响鼓、贝斯、和声和旋律的创作指令；对社区，它把音乐制作过程变成一场可观看、可参与、可二创的虚拟乐队表演。最终结果保留为 openDAW 中可编辑的 MIDI，而不是一段无法继续调整的黑盒音频。

### 为什么一定需要 AI？

> 因为观众不会用专业音乐语言表达。他们说的是“高级一点”“别太满”“想要 Boss 战的感觉”，系统必须结合当前作品理解这些模糊意见，再把它们转换成不同角色可以执行的音乐任务。固定按钮无法覆盖这种开放表达，而完全自由生成又很难保证好听，因此 DAWdex 使用 AI 理解意图，再用乐理规则和高质量 MIDI 托底。

## 四、唯一性赛道回答

### 为什么是你们？

> 我们不是从“还能在哪里加一个聊天框”出发。团队先亲手把 Codex、MCP 与 Ableton 跑通，确认 Agent 能够控制真实音乐软件；随后又主动放弃对外部 DAW 的依赖，转向 openDAW，把音乐制作能力直接放进产品。这个过程让我们认识到真正有价值的不是远程点击 DAW，而是让不会音乐的人也能看懂、参与并享受音乐制作。团队分别具备体验设计与传播、Agent 框架、音乐素材与工程集成能力，能够把概念做成完整 Demo。

### 你们解决了什么真实问题？

> 大多数人对音乐有感受，却没有表达专业音乐决策的语言。传统 DAW 把他们挡在门外，普通 AI 音乐生成器又只让他们反复抽卡。DAWdex 提供中间层：用户说人话，系统把它编译成专业、可解释、受乐理约束的任务，再让虚拟乐手把任务演奏出来。

### 真实用户验证

至少邀请三名目标用户：

| 用户 | 测试任务 | 关键问题 |
|---|---|---|
| 完全不会音乐的观众 | 用一句话让 Loop 变得更紧张 | 是否看懂自己的意见改变了什么？ |
| B 站/短视频观众 | 观看 90 秒 Demo | 是否愿意继续发送弹幕参与？ |
| 音乐创作者 | 检查结构化任务和 MIDI | 角色说法与实际结果是否一致？ |

不要只问“你喜欢吗”，要记录行为和具体原话。

## 五、90 秒赛道 Demo

```text
0–8 秒    “用弹幕指挥一支 AI 虚拟乐队”
8–18 秒   空舞台与屏幕内弹幕出现
18–28 秒  用户：“像最终 Boss 一样炸”
28–40 秒  制作人采用；总编曲师发布 Music Brief
40–62 秒  鼓手、贝斯手、键盘手领取任务并依次进入
62–75 秒  用户：“钢琴保留，贝斯再推进一点”
75–84 秒  贝斯任务更新并在下一循环加入
84–90 秒  最终作品 + 结构化指令 + 主题句
```

展示顺序必须让评委看到因果关系：

```text
哪条弹幕
→ 被谁采用
→ 编译成什么
→ 哪个角色执行
→ 音乐具体哪里变化
```

## 六、创意与成熟度证据

### 创意性

- 屏幕内弹幕作为音乐控制界面；
- 音乐制作过程成为虚拟乐队表演；
- 外行表达被分解给不同专业角色；
- 用户在作品生长过程中继续干预；
- “等待模型”被改造成可观看的角色交接。

### 成熟度

- 基于真实 openDAW，而不是视频假界面；
- 结构化 Schema；
- 角色文案与真实操作同源；
- 高质量 MIDI 素材与乐理硬规则托底；
- 模型失败有本地回退；
- 一步 Undo；
- 固定 90 秒脚本和预录视频。

## 八、禁止夸大

不能声称：

- 每个角色已经是独立 Agent，除非确实独立调用和合并；
- 音乐完全从零生成，如果实际使用检索和变体；
- 动画是实时音符驱动，如果只是演奏 Loop；
- 已接入真实 B 站弹幕，如果使用的是预设或本地输入；
- 支持所有 OpenAI-compatible API，如果没有逐项验证；
- 已完成完整歌曲，如果当前仍是 4/8 小节垂直切片；
- 已有正式风格音色目录，如果当前只完成 Vaporisateur 安全音色路径。

诚实地解释“高质量素材 + AI 意图理解 + 规则约束”会比夸大端到端生成更显成熟。
