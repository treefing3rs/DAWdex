# DAWdex 参赛赛道策略与提交回答

本文负责赛道选择：评估各赛道匹配度、确定主推与备选，并给出对应的提交回答策略。回答口径区分公有代码证据、拟展示切片与完整歌曲产品方向；赛道规则可能变化，最终报名前必须再次核对主办方页面和提交字段。

## 一、项目与主题

### 主题建议：Reverse / 反转

DAWdex 反转了评论、AI 音乐和 DAW 的关系：

1. 评论不再发生在作品完成之后，而是成为编曲入口；
2. AI 不直接交付一段成品音频，而是把意图、编排步骤和 DAW 操作连接起来；
3. 用户不需要学习 DAW，系统把外行语言编译为专业操作；
4. “加载过程”不再隐藏，而是成为角色化的音乐制作表演。

主题句：

> DAWdex reverses the role of comments: audience reactions are no longer feedback after creation; they become the interface of creation itself.

## 二、推荐赛道

### 主赛道：08｜干杯！创造属于你的 B 站新纪元

这是当前方向最自然的主赛道，因为弹幕从附属展示变成了核心交互入口。

匹配点：

- 以 B 站最具辨识度的弹幕文化为产品灵感；
- 观众从观看者变成共同创作者；
- 音乐区、鬼畜区、虚拟主播和直播都能理解；
- 拟展示切片计划呈现"弹幕 → 音乐意图 → 编排 → 可编辑轨道"；
- 虚拟角色、巡棚和多乐手逐轨演奏属于后续产品方向。

当前公有仓库没有接入真实 B 站弹幕。主赛道匹配来自产品方向，不是平台集成证据；
正式提交时必须明确使用本地输入或预设内容。

### 次赛道：05｜不做第一，做唯一

匹配点：

- 三名成员分别覆盖体验、Agent 和音乐执行。

## 三、主赛道提交回答

### 产品最大亮点是什么？

> DAWdex 把 B 站最有特色的弹幕，从观看后的反馈变成音乐创作的入口。观众只需要发送“再炸一点”“像最终 Boss 出场”“钢琴不要这么温柔”这样的日常语言，制作人 Agent 就会把它转换成 Creative Brief，通过 SQLite 检索本地素材，并提出结构化 Plan。公有代码可以核对 Plan、检索、审批、DAW 写入/回滚和操作引用；单乐器单轨四段式是拟展示切片。

### 如何服务 UP 主、用户和社区？

> 对 UP 主，它提出一种适合直播、音乐区、鬼畜区和虚拟主播内容的互动形式；对观众，弹幕不再只是情绪表达，而是音乐方向的输入；对社区，它把音乐制作过程变成可以观看、参与和二创的内容。当前仓库未接入真实 B 站弹幕；多人弹幕、多乐器和多轨表演都是产品方向。

### 为什么一定需要 AI？

> 因为观众不会用专业音乐语言表达。他们说的是“高级一点”“别太满”“想要 Boss 战的感觉”，系统必须结合当前作品理解这些模糊意见，再把它们转换成不同角色可以执行的音乐任务。固定按钮无法覆盖这种开放表达，而完全自由生成又很难保证好听，因此 DAWdex 使用 AI 理解意图，再用乐理规则和高质量 MIDI 托底。

## 四、唯一性赛道回答

### 为什么是你们？

> 我们不是从“还能在哪里加一个聊天框”出发。团队转向 openDAW，并在公有代码中建立了结构化 Plan、SQLite 检索、审批门、DAW 写入/回滚和操作引用。这个过程让我们认识到，真正有价值的不是远程点击 DAW，而是让不会音乐的人也能看懂意图如何变成编排和工程操作。拟展示切片将把这些代码事实组织成一段更直观的评委体验。

### 你们解决了什么真实问题？

> 大多数人对音乐有感受，却没有表达专业音乐决策的语言。传统 DAW 把他们挡在门外，普通 AI 音乐生成器又只让他们反复抽卡。DAWdex 提供中间层：用户说人话，系统把它编译成专业、可解释、受乐理约束的任务，再让虚拟乐手把任务演奏出来。

### 真实用户验证

至少邀请三名目标用户：

| 用户 | 测试任务 | 关键问题 |
|---|---|---|
| 完全不会音乐的观众 | 用一句话让 Loop 变得更紧张 | 是否看懂自己的意见改变了什么？ |
| B 站/短视频观众 | 观看 90 秒 Demo | 是否愿意继续发送弹幕参与？ |
| 音乐创作者 | 检查结构化任务和 MIDI | 角色说法与实际结果是否一致？ |

不要只问“你喜欢吗”，要记录行为和具体原话。

## 五、90 秒赛道 Demo

```text
0–8 秒    产品方向：“用弹幕指挥一支 AI 虚拟乐队”
8–18 秒   拟展示：用户弹幕“像最终 Boss 一样炸”
18–32 秒  代码证据：制作人 Agent 输出结构化 Plan
32–48 秒  拟展示：选定乐器与四段式编排
48–66 秒  代码证据：审批门、DAW 写入或回滚
66–82 秒  代码证据：Plan、目标对象与 Operation Reference
82–90 秒  明示拟展示切片与未来多乐器、多轨方向
```

展示顺序必须让评委看到因果关系：

```text
哪条弹幕
→ 编译成什么音乐意图
→ 形成什么编排步骤
→ 写入哪条轨道
→ 如何在工程中核对
```

## 六、创意与成熟度证据

### 创意性

- 屏幕内弹幕作为音乐控制界面；
- 外行表达被转换成结构化音乐意图；
- 编排步骤、目标轨道和工程操作可以相互对照；
- 拟展示的四段式切片可以扩展为虚拟乐队表演；
- 多乐器、多轨和完整歌曲保留为明确的产品方向。

### 成熟度

- 基于真实 openDAW，而不是视频假界面；
- Agent 输出结构化 Plan；
- SQLite 检索、候选排序和音乐指纹去重代码；
- 用户审批门；
- DAW 写入与失败回滚；
- Plan、目标对象与 Operation Reference 可以对照；
- 本地曾索引 193,320 条素材，但数据集与生成库不随公有仓库分发。

一个选定乐器、一条可编辑轨道、固定四段结构和 90 秒脚本属于拟展示证据，
在公有分支可运行前不能列入成熟度。

## 八、禁止夸大

不能声称：

- 每个角色已经是独立 Agent，除非确实独立调用和合并；
- 音乐完全从零生成，如果实际使用检索和变体；
- 动画是实时音符驱动，如果只是演奏 Loop；
- 已接入真实 B 站弹幕，如果使用的是预设或本地输入；
- 支持所有 OpenAI-compatible API，如果没有逐项验证；
- 单乐器、单轨、固定四段式已经在公有分支可运行，除非实现和运行证据已经补齐；
- 已完成多乐器、多轨或完整歌曲；这些仍是产品方向；
- 已有正式风格音色目录，如果当前只完成单一 Vaporisateur 音色路径。

把公有代码事实作为技术证据，把单轨四段式称为拟展示切片，把完整 AI 乐队称为产品方向。
