## 赛道 04 · Alibaba Cloud Qoder · 一个人=一支工程团队

**问题 1：你的项目解决了什么问题？目标用户是谁？**

DAWdex 解决的问题是：传统 DAW 门槛极高，不懂乐理的人无法参与音乐创作。目标用户是对音乐创作感兴趣但被专业工具拒之门外的普通人，以及需要快速获取编曲灵感的创作者。

**问题 2：描述你的人机协作工作流：AI 在项目中承担了哪些角色，你如何设计人与智能体的分工？**

DAWdex 的人机协作工作流：

1. **人类**：用自然语言弹幕表达音乐意图（"再炸一点""换成 R&B""钢琴柔一点"）
2. **AI 制作人 Agent**：理解情绪和场景，生成结构化 Creative Brief（风格/BPM/能量/编制）
3. **AI 编曲 Agent**：根据 Brief 从 19 万条 MIDI 素材库中检索最匹配的片段，设计音色参数，生成可解释的编排计划
4. **人类审批**：用户预览计划内容（将使用哪段素材、什么音色、写入哪个轨道），可批准/修改/拒绝
5. **AI 执行**：一键将批准的计划写入 openDAW 工程，自动配置合成器参数
6. **人类再干预**：随时撤销、替换、锁定满意的部分、继续迭代

设计原则：AI 永远先提案后执行，人类掌握最终决策权。每一步操作都是一个 Undo 事务，确保人类随时能回退。AI 不是黑盒生成器，而是一个透明的协作伙伴——它告诉你它要做什么、为什么这么做、用了什么素材，然后等你点头。

## 赛道 05 · 智能少年 · 不做第一，做唯一

**① 为什么是你们做这个？它和你们的痴迷、经历或优势有什么关系？**

我们三个人的交集恰好是这个项目存在的理由：

- 成员 A 是 UI/UX 设计师，痴迷于"让复杂事物变得有趣"的交互体验——他把专业 DAW 的冰冷界面变成了一间有角色、有故事的虚拟录音棚；
- 成员 B 是 AI Agent 工程师，长期研究如何让大模型产出结构化、可执行的指令而非空话——他设计了从弹幕到精确 MIDI 检索的完整智能体链路；
- 成员 C（我）是音乐数据工程师，负责 19 万条 MIDI 素材的索引、质量闸门和 WASM 音频引擎的编译集成——确保 AI 的决策最终能发出真实的声音。

没有任何一个现成产品同时做到：弹幕驱动 + AI 多角色编排 + 真实 MIDI 素材检索 + 浏览器内 WASM 实时合成 + 可编辑 DAW 工程输出。这个组合只有我们三个人的能力交集才能做出来。

**② 谁是它的真实用户？这几天有没有真人用过它？反馈是什么？**

真实用户是"想参与音乐创作但不会乐器也不懂乐理的人"——这是黑客松现场最常见的画像。活动期间我们让其他选手试用，反馈集中在两点：

1. "发条弹幕就能听到鼓和贝斯加进来，感觉自己真的在指挥"——参与感远超 Prompt-to-Audio；
2. "能看到 AI 选了哪条素材、为什么选它，不是黑盒"——透明度建立了信任。

## 赛道 08 · bilibili · 创造属于你的B站新纪元

**创造者好，请问你的产品最大的亮点是什么？是如何服务于B站UP主、用户和社区呢？**

**最大亮点：弹幕不再只是评论，而是直接驱动音乐创作。**

想象一个 UP 主开直播做音乐——过去观众只能发"好听""加油"；现在他们发"来一段 dubstep""更有力量感""钢琴温柔一点"，AI 制作人实时理解这些弹幕，从专业素材库中检索匹配片段，逐轨加入演奏。观众亲眼看到自己的弹幕变成了音乐的一部分。

这如何服务 B 站生态：
- **UP 主**：获得全新的直播互动形式——"弹幕共创音乐"，极高参与感和粘性
- **用户**：从被动消费者变为主动创作参与者，每条弹幕都有可能被 AI 采纳
- **社区**：诞生新内容品类——弹幕驱动的音乐创作直播/录播，天然适合二创和切片

B 站的弹幕文化是全球独一无二的；DAWdex 把这种文化从"评论层"提升到"创作层"。

## 赛道 11 · 超级合子 · 新国货出海 WOPC

**Q1. 项目的创意出发点——灵感来自哪里？一句话描述这个方向最大的价值？**

灵感来自 B 站弹幕文化——全球独有的实时互动方式。最大价值：把中国原创的弹幕交互范式与 AI 音乐创作结合，创造一种海外市场从未见过的"观众共创音乐"体验。

**Q2. 项目中运用了哪些 AI 技术和工具？**

- OpenAI GPT 系列模型：自然语言意图理解、Creative Brief 生成、编排计划规划
- 自建 SQLite 结构化检索引擎：19 万条 MIDI 素材按角色/风格/BPM/密度/音域索引
- Rust/WASM 实时 DSP 引擎：25 个音频设备插件在浏览器内实时合成
- 自研 RealUiEventBridge：工程状态 → 角色动画的单向同步

**Q3. 请阐述项目作品的潜在价值。**

弹幕是中国互联网的原创发明（2007 年 AcFun → Bilibili），但至今在海外没有成功的文化输出案例。DAWdex 用"弹幕驱动音乐创作"这一全新形式，让海外用户第一次理解弹幕的真正魅力——它不只是文字飘过屏幕，它是实时集体创作的工具。这种"中国交互范式 + AI 能力 + 音乐普世性"的组合，是一种全新的文化出海路径。

## 赛道 14 · 阶跃星辰 · 无人值守的前端自进化工厂

**用一句话描述你的系统：输入什么、无人干预地经历什么、输出什么？**

输入一条自然语言弹幕（如"来一段 dubstep"）；系统无人干预地完成：意图理解 → Creative Brief 生成 → 19 万素材库结构化检索 → 编排计划生成 → MIDI 写入 DAW 工程 → 合成器音色配置 → 实时播放；输出一份可编辑的多轨 DAW 工程和实时音频。

**你的系统由哪几个 Agent 组成？各自的角色与所用模型是什么？**

| Agent | 角色 | 模型 |
|---|---|---|
| Creative Director | 理解弹幕情绪和场景，输出结构化 Brief（风格/BPM/能量/编制） | GPT-5.4 via OpenAI API |
| Producer | 根据 Brief 从素材库检索 MIDI，设计音色参数，输出可执行 Plan | GPT-5.4 via OpenAI API |
| DawProjectAdapter | 将 Plan 翻译为 openDAW 工程操作（创建轨道、写入 MIDI、配置合成器） | 规则引擎（无模型） |
| FallbackPlan | 模型不可用时，根据能量词库程序化生成 Pattern | 规则引擎（无模型） |

当 Codex CLI 可用时，Creative Director 和 Producer 通过 Codex 本地推理（零 API 费用）；不可用时自动 fallback 到 OpenAI 兼容 API。

## 赛道 17 · Superun · Context to Code

**① 为什么这个问题值得解决？它是否真实存在？是否每天都有人经历？**

"想做音乐但不会 DAW"是一个每天数百万人经历的问题。B 站/YouTube 上"零基础学编曲"类视频播放量动辄百万，但绝大多数观众看完教程打开 DAW 后依然无从下手。问题不是缺教程，而是 DAW 本身的操作范式对非专业人士不友好。

**② 为什么你最适合解决它？你的经历、专业、兴趣，是否让你拥有别人没有的 Context？**

我（成员 C）是物联网工程专业的大三学生，同时在 ListenHub（音频科技公司）实习做运营和开发。我自己就是一个"对音乐极度感兴趣但不会乐器"的人——这正是 DAWdex 的目标用户画像。我的 Context 来自亲身经历：下载过 FL Studio、Ableton、GarageBand，每次打开都被密密麻麻的参数劝退。这种挫败感让我确信：解决方案不是"更好的教程"，而是"根本不需要你操作 DAW"。

**③ 为什么 AI 是解决它的最佳方式？**

因为"把日常语言翻译成专业音乐操作"本质上是一个语义理解+结构化输出的问题——这恰好是大语言模型最擅长的事。在 DAWdex 中，AI 不是在"生成音频"（那是黑盒），而是在做决策：理解你说的"再炸一点"意味着"鼓点密度+20%、低频增益+3dB、加入 Hi-hat 16 分音符"，然后从真实素材库中找到匹配片段。AI 改变的是整个工作流——从"人学习工具"变为"工具理解人"。

我们在 Superun 上搭建了 DAWdex 链路中"弹幕意图理解"的 Workflow：输入一条中文弹幕，输出结构化 Creative Brief（包含风格、BPM、能量等级、目标乐器编制）。这个 Workflow 作为 DAWdex Agent Server 的前置环节。

## 赛道 06 · 亚马逊 · Quick Quick Quick（如确认可报）

**你用 Amazon Quick 或者 Kiro 用来干过的最快最高效的项目是什么？具体阐述一下是如何高效完成的**

我们在 DAWdex 开发过程中使用 Kiro 辅助完成了 Agent Server 的 API 设计和错误处理逻辑。具体场景：需要在 2 小时内实现一个支持 SSE 流式返回的 `/v1/plan` 端点——接收弹幕文本和工程快照，流式返回进度更新（"正在理解意图…""正在检索素材…""编排计划生成中…"），最终返回结构化 JSON Plan。

使用 Kiro 的高效之处：
1. 描述需求后 Kiro 直接生成了完整的 SSE 骨架代码（Node.js HTTP server + 分阶段 emit）
2. 我们只需要填入业务逻辑（模型调用、素材检索、Plan 验证）
3. 从零到可运行的 streaming endpoint 只用了 40 分钟

这体现了"快快快"的核心：AI 处理样板代码，人类专注领域逻辑。
