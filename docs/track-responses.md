## 赛道 04 · Alibaba Cloud Qoder · 一个人=一支工程团队

**问题 1：你的项目解决了什么问题？目标用户是谁？**

DAWdex 解决的问题是：传统 DAW 门槛极高，不懂乐理的人无法参与音乐创作。目标用户是对音乐创作感兴趣但被专业工具拒之门外的普通人，以及需要快速获取编曲灵感的创作者。

**问题 2：描述你的人机协作工作流：AI 在项目中承担了哪些角色，你如何设计人与智能体的分工？**

DAWdex 的人机协作工作流：

1. **人类**：用自然语言弹幕表达音乐意图（"再炸一点""换成 R&B""钢琴柔一点"）
2. **AI 制作人 Agent**：理解情绪和场景，生成结构化 Creative Brief（风格/BPM/能量/编制）
3. **AI 编排**：根据 Brief 调用 SQLite 检索器查找本地候选，生成可理解的编排步骤
4. **人类审批**：用户预览将使用的素材、乐器、段落结构和目标轨道，可批准或调整
5. **AI 执行**：把批准的计划写入 openDAW，并保留计划、目标对象和实际操作之间的引用
6. **人类继续编辑**：在 openDAW 中检查结果并继续修改

公有代码可以核对结构化 Plan、SQLite 检索、审批门、DAW 写入/回滚和操作引用。一个选定乐器、一条可编辑轨道和固定的 `Intro → Verse → Chorus → Bridge` 是拟展示的前端切片，尚未作为公有分支可运行功能落地；多乐器、多轨和完整歌曲是后续产品方向。

## 赛道 05 · 智能少年 · 不做第一，做唯一

**① 为什么是你们做这个？它和你们的痴迷、经历或优势有什么关系？**

我们三个人的交集恰好是这个项目存在的理由：

- 成员 A 是 UI/UX 设计师，痴迷于"让复杂事物变得有趣"的交互体验——他把专业 DAW 的冰冷界面变成了一间有角色、有故事的虚拟录音棚；
- 成员 B 是 AI Agent 工程师，长期研究如何让大模型产出结构化、可执行的指令而非空话——他设计了从弹幕到精确 MIDI 检索的完整智能体链路；
- 成员 C（我）是音乐数据工程师，负责本地 MIDI 数据的索引、质量检查和 WASM 音频引擎集成。公有仓库保留检索与建库代码；本地曾索引 193,320 条素材，但数据集本身不随仓库分发。

我们的切入点是把弹幕交互、结构化音乐意图、真实 MIDI 检索、浏览器内音频引擎和可编辑 DAW 工程放进同一条可追溯链路。团队三人的体验设计、Agent 和音乐工程能力，分别对应这条链路的关键部分。

**② 谁是它的真实用户？这几天有没有真人用过它？反馈是什么？**

目标用户是"想参与音乐创作、但不会乐器或不熟悉 DAW 的人"。本次公开提交材料尚未附带可核验的外部用户测试记录，因此不引用未经记录的反馈。当前可验证的是结构化 Plan、SQLite 检索、审批门、DAW 写入/回滚和操作引用；四段式单轨体验仍是拟展示切片。

## 赛道 07 · 小红书 · Build in Public

**1）你的项目是什么？解决了谁的什么问题？**

DAWdex 是弹幕驱动的 AI 乐队 Agent。它让不熟悉乐理和 DAW 的人用日常语言表达音乐方向，再把这句话转换成可理解的编排步骤和可追溯的工程操作。

**2）你希望在小红书上，用什么方式让它被更多人看见？**

我们计划发布"DAWdex 开发日志"系列笔记：
- 第一条：项目介绍 + 核心 Demo 录屏（弹幕发出 → AI 编排 → 音乐响起的完整过程）
- 后续：拆解技术选型故事（为什么使用 WASM？本地 19 万级索引怎样构建？）
- 互动：邀请观众用弹幕投票决定下一首歌的风格

这些是发布计划，不是已完成的小红书运营证据；正式申报前需补充公开链接和时间记录。

**3）开发过程中，吸收了哪些小红书用户、作者的建议或者启发？**

我们的产品假设是：教程可以解释知识，却未必能消除第一次打开 DAW 时的操作门槛。因此 DAWdex 不再增加一套教程，而是尝试把用户的日常表达转换成结构化音乐任务。只有在补齐具体笔记链接、作者建议或公开互动记录后，才把小红书用户启发写成已发生事实。

## 赛道 08 · bilibili · 创造属于你的B站新纪元

**创造者好，请问你的产品最大的亮点是什么？是如何服务于B站UP主、用户和社区呢？**

**最大亮点：弹幕不再只是评论，而是直接驱动音乐创作。**

想象一个 UP 主开直播做音乐——过去观众只能发"好听""加油"；现在他们发"来一段 dubstep""更有力量感""钢琴温柔一点"，AI 制作人把弹幕转换成结构化音乐意图、编排步骤和 DAW 操作。观众可以沿着这条因果链，看见自己的弹幕怎样进入音乐工程。

这如何服务 B 站生态：
- **UP 主**：获得"弹幕共创音乐"的直播互动形式
- **用户**：从被动观看者变为可以提出音乐方向的参与者
- **社区**：获得适合直播、录播、二创和切片的音乐制作叙事

DAWdex 借用 B 站最有辨识度的弹幕文化，把弹幕从"评论层"推进到"创作入口"。当前公有仓库没有接入真实 B 站弹幕；多人弹幕共创、多乐器和多轨乐队均是产品方向。单乐器、单轨、固定四段式是拟展示切片，不是已落地的公有分支功能。

## 赛道 10 · 蓝盒子 · Hack the Rest

**想听听，做这个项目的过程中，最打动你们团队的是什么？**

最打动我们的，是看见一句日常语言不再只停留在聊天框里：公有代码已经能把它组织成结构化 Plan，并把获批计划与 DAW 写入结果通过 Operation Reference 关联起来。单轨四段式仍是拟展示切片。

那个瞬间我们意识到：**我们做的东西本身就是一种休息。**

音乐是人类最古老的疗愈方式。但"创造音乐"一直被专业门槛阻隔在大多数人之外。DAWdex 的意义不只是降低了门槛——它把"创造音乐"这件事变成了一种轻松的、可以用一句话参与的休息方式。你不需要练琴十年，不需要学和声理论，发一条弹幕，听着 AI 乐队为你演奏，这本身就是一种创造性的放松。

灵感来源：我们注意到很多人在工作累了之后会打开 Lo-fi 音乐直播"挂着听"——但他们无法参与。DAWdex 让"挂着听"变成"随口说一句就能改变音乐走向"。

## 赛道 11 · 超级合子 · 新国货出海 WOPC

**Q1. 项目的创意出发点——灵感来自哪里？一句话描述这个方向最大的价值？**

灵感来自 B 站弹幕文化。这个方向的价值，是把中国互联网中具有辨识度的弹幕交互范式与 AI 音乐制作结合，让观众语言成为创作入口。

**Q2. 项目中运用了哪些 AI 技术和工具？**

- OpenAI GPT 系列模型：自然语言意图理解、Creative Brief 生成、编排计划规划
- 自建 SQLite 结构化检索引擎：公有仓库包含建库与检索代码；本地曾索引 193,320 条素材，数据集不随仓库分发
- Rust/WASM 音频引擎：在浏览器内运行 openDAW
- 操作引用：把 Agent Plan、目标轨道和实际工程操作关联起来

**Q3. 请阐述项目作品的潜在价值。**

DAWdex 把弹幕从覆盖在内容上的评论，转成进入音乐工程的自然语言输入。这种"弹幕交互 + AI 意图理解 + 可编辑音乐工程"的组合，为跨语言的观众共创提供了一个可继续验证的方向。

## 赛道 14 · 阶跃星辰 · 无人值守的前端自进化工厂

**用一句话描述你的系统：输入什么、无人干预地经历什么、输出什么？**

DAWdex 不是完全无人值守系统：公有代码明确保留用户审批门。可核对的链路是自然语言 → 结构化 Plan → SQLite 检索 → 用户审批 → DAW 写入或回滚 → Operation Reference。单乐器、单轨和固定 `Intro → Verse → Chorus → Bridge` 是拟展示切片，尚不是公有分支可运行输出；如赛道强制要求全程无人干预，则不应以当前形态申报。

**你的系统由哪几个 Agent 组成？各自的角色与所用模型是什么？**

| 组件 | 角色 | 实现 |
|---|---|---|
| Creative Director | 理解弹幕情绪和场景，输出结构化 Brief（风格/BPM/能量/编制） | Agent 的意图阶段 |
| Producer | 根据 Brief 检索 MIDI，输出可理解的编排 Plan | Agent 的编排阶段 |
| DawProjectAdapter | 将 Plan 翻译为 openDAW 工程操作（创建轨道、写入 MIDI、配置合成器） | 规则引擎（无模型） |

Creative Director 和 Producer 是同一 AI 乐队 Agent 中的逻辑阶段；除非有独立调用和协作证据，不把它们描述为多个已经交付的独立 Agent。

## 赛道 17 · Superun · Context to Code

**① 为什么这个问题值得解决？它是否真实存在？是否每天都有人经历？**

"想做音乐但不会 DAW"是一个真实存在的入门障碍。教程可以解释知识，却不能替用户把一句模糊感受转换成具体的音乐决策和工程操作；DAWdex 针对的正是这段翻译成本。

**② 为什么你最适合解决它？你的经历、专业、兴趣，是否让你拥有别人没有的 Context？**

我（成员 C）是物联网工程专业的大三学生，同时在 ListenHub（音频科技公司）实习做运营和开发。我自己就是一个"对音乐极度感兴趣但不会乐器"的人——这正是 DAWdex 的目标用户画像。我的 Context 来自亲身经历：下载过 FL Studio、Ableton、GarageBand，每次打开都被密密麻麻的参数劝退。这种挫败感让我确信：解决方案不是"更好的教程"，而是"根本不需要你操作 DAW"。

**③ 为什么 AI 是解决它的最佳方式？**

因为"把日常语言翻译成专业音乐操作"需要理解开放表达，再输出稳定的结构化结果。在 DAWdex 中，AI 不直接交付一段黑盒音频，而是把"再炸一点"这样的表达转换成 Creative Brief、素材选择、编排步骤和目标明确的 DAW 操作。AI 改变的是工作流——从"人先学会工具"变为"工具先理解人的意图"。

只有在能够提供 Superun Workflow 的公开链接、运行记录和与当前代码的对应关系时，才使用平台集成表述。公有仓库本身只能证明 DAWdex 的结构化 Plan 链路，不证明 Superun 上已经存在可核验部署。
