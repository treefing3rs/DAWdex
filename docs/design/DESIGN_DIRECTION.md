# DAWdex 前端设计方向

> 版本：v3.0 · 2026-07-25
> 当前代码基线：PR #12
> 取代旧版中“全应用弹幕”“Mock 默认运行”“多房间尚未实现”等条款

## 一、设计定义

> **DAWdex 的前端把 openDAW 翻译成一部可以操作的动画片：DAW 功能成为录音棚房间里的物件，播放和 Agent 状态成为乐队成员的动作，弹幕是用户指挥乐队的常驻自然语言。**

它不是把专业 DAW 藏掉，而是为同一工程提供三种视角：

1. 动画录音棚：让非专业用户理解因果；
2. 乐队会议与证据抽屉：解释 Agent 做了什么；
3. openDAW 专业视图：继续编辑并证明修改真实发生。

## 二、设计原则

### 2.1 因果真实性

```text
用户说了一句话
→ 制作人采纳
→ 角色领取任务
→ openDAW 执行
→ 轨道确认发声
→ 角色开始演奏
```

任何视觉状态都必须指向真实事件。特别是：

- `RoleStateChanged(performing)` 只表示 Agent 认为角色应演奏；
- `TrackAudibleChanged(audible=true)` 才允许实际演奏动画；
- Pause/Stop 时动画和走带同步停止；
- Mock、本地回退、Codex 和 OpenAI 来源必须可区分；
- UI 不自行解析模型自由文本。

### 2.2 世界内 UI

专业概念优先长在录音棚世界里：

| DAW/Agent 概念 | 世界内表达 |
|---|---|
| Track / Role | 乐手 |
| Instrument | 房间中的乐器或设备 |
| Transport | REC、走带和节拍 |
| Agent State | 等待、准备、排队、演奏、失败动作 |
| Adopted Prompt | 房间灯牌 |
| Plan / Receipt | 乐队会议 |
| Error | 雪花噪点和系统弹幕 |
| Song Blueprint | 控制室编曲白板 |
| Section Lock | 卡片图钉 |

无法诚实绑定真实状态的物件保持装饰，不伪装成控件。

### 2.3 两层界面

- **屏幕世界**：房间、角色、弹幕、REC、走带、状态灯和错误反馈。
- **屏幕外控制台**：输入、六种干预、Provider、证据抽屉和专业视图入口。

像素风集中在屏幕世界；外壳保持克制、可读和适合长时间操作。

PR #12 将“专业视图入口”落实为收起外壳：openDAW 从未被卸载或复制，
只是被演播厅覆盖。点击工作台、按 `Esc` 或使用 `?workbench=1` 后，外壳
收成右缘侧拉抽屉并让交互穿透到底层 openDAW；事件桥持续同步。

## 三、当前视觉系统

### 3.1 外壳

- 暖白页面背景；
- 深棕黑复古监视器；
- 圆角 bezel、内高光和外投影；
- 顶栏包含 DAWdex、Provider 状态、ON AIR、频道、投屏和重播；
- 底部控制台承载输入与快速操作。

### 3.2 屏幕

- 主频道使用 `studio_night_loop.mp4`；
- 静音自动播放，失败时降级到 `studio_night.jpg`；
- 弹幕、REC 和走带是跨房间全局层；
- 夜晚录音棚是唯一正式皮肤，不再维护昼夜切换。

### 3.3 角色

当前运行态：

- drums、bass、keys：轨道角色，参与等待/准备/排队/演奏/失败状态；
- producer：控制室常驻，不是普通轨道角色；
- guitarist：v2 素材已入库，尚未接入真实轨道角色。

角色素材采用写实比例的细像素画风，与夜景场景的暖金轮廓光保持一致。旧 V3/Q 版文件保留为历史资产，不作为当前默认。

### 3.4 入场

角色开局不在房间内。第一次收到任务、状态或发声事件时，从门外以 8-bit 步进走位入场。演奏动作只作用于角色图片子元素，避免与入场位移互相覆盖。

### 3.5 电梯

首次挂载显示 2.6 秒“上楼进棚”过场，用户可跳过。它是氛围叙事，不伪装引擎加载进度。

## 四、弹幕

### 4.1 范围

弹幕只在复古监视器的屏幕内部移动，不覆盖外壳、输入、证据抽屉或专业编辑器。

正式表述：

> 弹幕是唯一常驻自然语言输入；房间物件、干预按钮和专业视图是操作捷径。

### 4.2 身份

| 身份 | 表达 |
|---|---|
| 用户 | 主体白字 |
| AI 乐迷 | 明确的 AI 徽标 |
| 系统 | 状态和错误样式 |
| 角色/制作人 | 角色锚色与可追踪回执 |

用户原文立即上屏；采纳后升格为灯牌。Agent 文案从结构化 Plan/Receipt 派生，不独立编故事。

### 4.3 安全

- 弹幕层 `pointer-events: none`；
- 长文本截断；
- 不遮角色脸和关键走带信息；
- 专业视图打开时不覆盖工程内容；
- AI 观众不得冒充真人。

## 五、房间与频道

当前六个频道：

| ID | 房间 | 当前作用 |
|---|---|---|
| `main` | 演播大厅 | 默认夜景演奏舞台 |
| `drums` | 鼓棚 | 鼓手与鼓组空间 |
| `strings` | 吉他贝斯棚 | 贝斯手；吉他扩展位 |
| `keys` | 键盘阁楼 | 键盘手空间 |
| `control` | 控制室 | 制作人、证据与未来编曲白板 |
| `lounge` | 休息室 | 观众和候场叙事 |

频道通过顶栏 `CH ‹ 房间名 ›` 硬切，保留 TV 切台气质；支持 `?room=<id>` 深链。

当前只是“房间选择 + 演员表 + 背景”。乐器、门牌、沙发和调音台尚未全部成为真实热点。

## 六、状态与动效

轨道角色状态：

```text
waiting
→ preparing
→ queued
→ performing
→ waiting

any active state → failed
failed → waiting
```

动效规则：

- 一拍时长来自 `60 / BPM`；
- 走带位置由 `TransportChanged` 校准；
- 轨道静音时角色立即退出演奏；
- Failed 使用角色区域雪花和系统弹幕；
- `prefers-reduced-motion` 下关闭非必要移动；
- 房间切换硬切，不用与音乐状态无关的长转场。

## 七、证据与操作

乐队会议至少显示：

- 用户弹幕；
- Creative Brief 摘要；
- Plan 标题、理由和动作；
- 角色任务与可听结果；
- MIDI Asset 或操作引用；
- Apply、Fallback、Failure 和 Undo。

快速操作：

```text
保留 | 更有力量 | 更轻松 | 换乐器 | 重新生成 | 撤销
```

除“保留”和“撤销”外，当前其余操作重新进入计划审批链，不直接假装已经改变音乐。

评委或用户质疑“这是否是真 DAW”时，可以直接收起演播厅，操作同一工程。
工作台模式与投屏模式互斥；返回演播厅后使用收起期间持续同步的最新状态。

## 八、Mock 与真实模式

默认进入真实模式。

Mock 只能通过：

- URL `?mock=1`；
- 顶栏 `↻`。

Mock 播放时暂停真实桥，结束后恢复。Mock 是 90 秒演示资产，不是产品状态来源。

## 九、完整歌曲前端

当前循环进度条只能表达 4/8 小节局部过程。完整歌曲需要在控制室增加编曲白板：

```text
┌──────────────────────────────────────────────────┐
│ INTRO │ VERSE 1 │ CHORUS 1 │ VERSE 2 │ BRIDGE  │
│  8bar │  16bar  │   8bar    │  16bar  │  8bar   │
└──────────────────────────────────────────────────┘
```

每张 Section 卡片显示：

- 名称和小节范围；
- 当前能量；
- 主要角色；
- 来源/变体关系；
- 当前播放；
- 已锁定；
- 待审批修改。

白板事件建议在现有 v0.1 契约上增量增加：

```text
BlueprintChanged
SectionChanged
SectionLocked
PhraseDeveloped
```

白板不能自行从时间线猜测结构；它消费正式 Song State。

### 多轮对话反馈

用户说“第二次副歌更炸，但保留 Lead”时：

1. 对应 Chorus 2 卡片高亮；
2. Lead 显示锁定图钉；
3. Drums/Bass 进入 preparing；
4. Plan 卡显示目标 Section；
5. 写入后卡片版本变化；
6. 走带到该 Section 且轨道发声，角色才演奏。

这使用户看见“改的是整首歌的哪一部分”，而不是只看循环内又多了一层。

## 十一、完成标准

一个视觉功能只有同时满足以下条件才算完成：

1. 有明确的真实事件或用户操作来源；
2. 不会在失败或静音时产生错误叙事；
3. 能在 Mock 和真实模式中区分来源；
4. 能说明它对应的 DAW/Agent 概念；
5. 有降级和可访问性处理；
6. 不阻碍专业编辑和 Undo。

DAWdex 的游戏感来自因果，而不是装饰数量。

## 十二、冒险游戏管线 · 房间物件方法论

巡棚五个房间（鼓棚/吉他贝斯棚/键盘阁楼/控制室/休息室）与演播大厅共用同一套
「冒险游戏标准管线」，每个房间都是可交互的 DAW 替代界面，而不是一张插图。

### 12.1 管线六步

1. **物件分层**：从房间底图抠出物件替身 sprite（矩形裁剪、同像素）。
2. **原位盖回**：替身叠回原坐标（1600 宽帧、cover 可视高 950px 标定），
   静态时与底图零像素差异——没有任何悬浮层可见。
3. **轮廓命中**：命中层与替身共用同一条 clip-path 多边形，沿物件真实轮廓，
   不用矩形框选不规则物件。
4. **无遮罩 hover**：`slot:has(hit:hover) img { filter: brightness(1.45) }`，
   物件自身像素变亮（clip 裁剪后只亮轮廓）；另有 8-bit 闪光点做可交互引导，
   hover 过一次即永久熄灭。
5. **点击开面板**：点击物件 → 下方键盘屏点亮（deck-focus 运镜），
   显示该物件对应的 DAW 功能面板，附「在 openDAW 中打开」出口。
6. **演出态皮肤**：走带播放时房间循环视频淡入（整棚苏醒），
   物件层同步淡出；暂停回到静帧与静态物件。

### 12.2 行为与状态模型

每个物件处于三态之一：

- **自动动（事件绑定，无需交互）**：REC 灯牌（对应角色 TrackAudibleChanged
  或走带播放时点亮）、演出态视频（TransportChanged.isPlaying）。
  铁律不变：没有真实事件就没有动作。
- **交互动（hover/click 触发）**：闪光点引导、轮廓变亮、功能面板。
  平时完全静止。
- **纯装饰（永不动）**：场景其余一切。像素场景一动就糊，克制是第一原则。
