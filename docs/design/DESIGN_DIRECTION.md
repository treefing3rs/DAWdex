# DAWdex 设计方向 v2 · Kimi 风 × 伪 8-bit 演播机

> 版本：v2.3 · 2026-07-25（v1 三方案对比见 `DESIGN_BRIEFS.md`；v2.1 融合用户自制场景；v2.2 Phase-1 落地校准 + Studio Complex 映射 + 外壳定义；v2.3 冲突裁决——弹幕范围/夜晚唯一皮肤/角色重做。**本版取代仓库旧 v2.2 中的"全屏弹幕遮罩"条款，弹幕范围以 §13.1 裁决为准：只在屏幕内**）
> 目标仓库：<https://github.com/treefing3rs/DAWdex>（本地副本 `repo/`）

## 1. 方向定义

**一句话：把 DAWdex 做成一台"复古演播机"——Kimi 式的克制外壳 + 伪 8-bit 像素的屏幕内容，屏幕里的每一个像素都是真实状态。**

两条血脉的融合方式：

| 血脉 | 负责什么 | 具体表现 |
|---|---|---|
| **Kimi 风格** | 外壳与交互层 | 大面积留白、细发丝边框、克制的圆角、系统字体、低饱和中性色；输入框、按钮、面板的呼吸感 |
| **伪 8-bit 像素** | 屏幕内容层 | 角色、舞台、状态灯、跑马灯全部像素化；刻意低帧率（8–12fps）动画；像素进度条 |

**关键原则：外壳是现代产品，屏幕里是复古现场。** 用户摸到的是 Kimi 的顺滑，看到的是游戏机的灵魂。两层不混淆——像素风绝不蔓延到输入框和按钮上，否则变成廉价主题皮肤。

### 复古外壳形态（三选一，建议 TV）

1. **复古电视机（建议）**：圆角 CRT 机身框住舞台区，右上角一枚像素 `ON AIR` 灯 + 频道旋钮（旋钮即角色切换），底部扬声器格栅恰好是弹幕输入区的位置。
2. **掌上游戏机**：舞台是屏幕，下方十字键/AB 键映射为 FR-09 的六个操作（保留/更有力/更轻松/换乐器/重新生成/撤销）。交互映射最妙，但屏幕占比小。
3. **监视器/显示屏**：最接近 Brief A 的终端气质，最稳妥但记忆点最弱。

## 2. 屏幕内容 = 真实状态（核心设计约束）

屏幕不是装饰动画，**每个视觉元素绑定一个真实数据源**：

| 屏幕元素 | 数据源 | 交互 |
|---|---|---|
| 角色 loop 动画 | openDAW 对应轨道是否发声（PRD：角色只按轨道有声/无声切换演奏状态） | 点击角色 → 定位/选中对应轨道 |
| 角色头顶状态灯 | Agent 状态机：等待/思考/准备/演奏/失败 | 点击 → 展开该角色最近一条工作回执 |
| 像素循环进度条 | 工程权威 BPM + 循环边界（FR-06） | 无（纯指示） |
| 跑马灯大标题 | 被制作人采纳的弹幕原文 | 悬停暂停 |
| 雪花噪点 | 模型失败 / 校验未过 / 本地回退触发 | 点击进入事件日志 |
| 底部弹幕流 | 真弹幕 + Agent 附和 + AI 乐迷 + 系统消息 | 点击弹幕 → 高亮它影响的轨道 |

**说一套做一套在这个界面里没有藏身之地**——角色不动就是轨道没响，雪花一出现就是真的出错了。

## 4. 弹幕系统（核心亮点）

参考 B站弹幕，但比 B站多一层：**Agent 也是弹幕参与者**。

### 4.1 弹幕类型与视觉区分

| 类型 | 样式 | 说明 |
|---|---|---|
| 真人观众 | 白字 | 默认弹幕 |
| **制作人 Agent** | 青色描边 + `🎛 制作人` 小徽标 | 裁决、附和、追问 |
| **乐手 Agent** | 角色色描边 + 角色小徽标 | "鼓手收到，四拍底鼓安排上了" |
| AI 乐迷 | 灰字 + `AI 乐迷` 徽标（PRD 强制标记） | 气氛组 |
| 系统 | 居中底部短暂停留，不滚动 | "新轨将在下一循环进入" |

### 4.2 弹幕只活在屏幕里

弹幕层 `absolute` 覆盖在**电视屏幕内部**（不是整个页面），`pointer-events: none` 穿透；多轨道分层速度；长文本截断；危险内容过滤。这样弹幕永远不与外壳控件争抢，视觉上也像"节目的一部分"。

### 4.3 Agent 附和机制

- 用户发送弹幕后，**原文立即上屏飘过**（零延迟反馈）。
- 制作人 Agent 的附和/回复**也以弹幕形式发出**（而不是只在对话框里）——观众看到自己的弹幕和 Agent 的回应在同一条河里漂，这是"乐队真的在听你说话"的最强证据。
- 采纳的弹幕升格为**跑马灯大标题**；被拒绝的弹幕正常飘过，制作人弹幕简短说明原因。
- 附带规则：Agent 弹幕必须可溯源——点击 Agent 弹幕展开对应回执/指令。

### 5.2 每角色需要 3 组素材

| 素材 | 内容 | 用途 |
|---|---|---|
| **待机 idle** | 角色安静站着/坐着，轻微呼吸摆动 | 轨道未加入或未发声 |
| **演奏 playing** | 完整演奏动作 loop（打鼓/拨弦/按键/扫弦/推推子） | 轨道发声中 |
| **准备 ready**（可省） | 乐器上手、看向制作人 | 任务已领取，等待循环边界 |

失败态不需要素材——用**雪花噪点转场**覆盖该角色区域即可。

### 5.3 生产步骤

1. **图片（已完成第一轮）**：image_generation 生成单帧立绘。如需更连贯的动画，应补生成「同角色 2–4 个关键姿势」（用 `image-to-url` + `--reference-image` 保持角色一致性）。
2. **Loop 视频**：以立绘为参考帧做图生视频（img2video），要求：
   - 时长 2–4 秒，**首尾帧可无缝循环**（循环点对齐 128BPM 的一拍或半拍 ≈ 0.47s/0.94s 的整数倍）；
   - 动作幅度小而密（手腕、头部、身体重心），不要做位移大的动作；
   - 保持像素风与角色色，透明/纯色底便于抠像；
   - 每个角色至少 idle、playing 两段。
3. **Codex 产品化**：视频到货后交给 Codex 做工程化，验收标准：
   - 转封装为 Web 友好格式（循环 `<video muted loop playsinline>` 或 WebM/APNG），`image-rendering: pixelated` 保持像素锐利；
   - 封装为 `PerformerSprite` 组件：props = `{role, state, accentColor}`，按状态切换播放源，切换时用 100ms 雪花噪声遮罩掩盖接缝；
   - 状态机与 openDAW 轨道发声事件对接（`playing ⇄ idle`），与 Agent 事件对接（`thinking/ready` 显示状态灯）；
   - 失败/降级路径：视频加载失败时回退为静态 PNG + CSS 抖动动画，保证 Demo 不翻车。

### 5.4 素材规格

- 画布：2:3 竖版，角色占高约 80%，透明 PNG/WebM(VP9 alpha)；
- 舞台上显示高度约 160–220px，源素材 1024×1536 足够；
- 像素颗粒度：角色边缘可见明确像素块，禁止平滑渐变糊边。

## 9. v2.1 · 场景融合：房间即工程（游戏化 DAW）

### 9.1 已有场景素材与用途

用户自制 4 张像素场景（`assets/scenes/`），全部位于外壳屏幕内部：

| 素材 | 内容 | 设计用途 |
|---|---|---|
| `...meutpo...png` | 控制室夜景：大调音台、三联 DAW 监视器、暖灯 | **主场景·演出态**。房间内嵌界面（diegetic UI）的主战场 |
| `...mfohwp...png` | 录音棚夜景：设备架、REC 监视器、沙发上吉他、暖灯 | **主场景·日常态/候补主场景** |
| `...vicbn2...png` | 同一录音棚白天版 | **状态皮肤**：白天 = 等待/排练；夜晚暖灯 = 演出中/作品完成 |
| `...rclp3n...png` | 「DAY 9」电梯间，背吉他的人 | **加载/开场画面**：进棚 = 上电梯，游戏感的第一步 |

判断：方向完全成立，而且这四张图里藏着这套设计最关键的东西——**场景自带"屏幕"和"控制台"**。REC 监视器、三联 DAW 显示器、调音台通道、音箱，这些不是装饰，它们是天然的"界面内嵌界面"锚点。

### 9.2 核心手法：Diegetic UI（界面内嵌界面）

游戏沉浸感的第一原则：UI 画在世界里，而不是浮在世界上面。DAWdex 的每个真实数据都找一个场景内的"宿主"：

| 场景内锚点 | 绑定的真实数据 | 呈现方式 |
|---|---|---|
| REC 监视器 | 权威时钟：BPM / 调性 / BAR / 循环进度 | 叠加像素字滚动屏，`01:23:45` 换成实时走带 |
| 调音台通道条 | openDAW 每轨电平 | 通道灯随电平跳动（CSS/canvas 热点） |
| 三联 DAW 显示器 | openDAW 轨道概览（Region 色块 = 角色色） | 缩小版"工程视图"；点击放大为抽屉 |
| 沙发上的吉他 | 吉他手轨道未加入 | 乐器静置；轨道加入时角色入场拿起乐器 |
| 音箱 / 设备架灯 | 轨道发声状态 | 发声时喇叭微振、设备灯亮 |
| 房间灯牌 / 墙面 | 被采纳弹幕原文 | 升格为房间内的像素灯牌字幕 |
| 吊灯 / 整体光照 | 会话能量（energyChange） | 能量越高灯越暖越亮；昼夜皮肤切换 |
| 房间本身 | 模型失败 / 回退 | 灯泡闪烁 + 雪花噪点掠过屏幕 |

**实施要点：沉浸感来自"少量精动的热点"，不是整图动画。** 场景图保持静态，只在锚点位置叠加小尺寸发光/跳动元素（绝对定位 + CSS 动画 + 可选小 canvas）。整图不做视差、不做缩放——像素图一动就糊。

### 9.3 游戏化系统（全部绑定真实数据，无一装饰）

1. **入场系统**：新轨不是"出现"，是角色**走进房间**。循环边界到达 → 房间灯一闪 → 角色从侧门/电梯入位 → 乐器上手 → 下一拍开始发声。这是 Flow 5 的游戏化翻译，也是 Demo 最爽的瞬间。
2. **状态灯系统**：角色头顶像素状态灯（等待/思考/准备/演奏/失败），与轨道发声严格同步，点击展开该角色回执。
3. **弹幕河**：弹幕在房间上半部飘过（场景内，不遮角色脸），五种身份样式同 v2 §4；Agent 附和弹幕是互动感的核心填充。
4. **升格时刻**：弹幕被采纳 → 原文短暂成为房间灯牌大标题 + 制作人弹幕宣布理由。
5. **昼夜皮肤**：开场白天（排练感）→ 首条弹幕被采纳后渐入夜景暖灯（演出感）→ 作品完成循环时满灯。状态迁移本身成为叙事。

### 9.4 开场：上楼进棚

「DAY 9」电梯图直接作为加载画面：打开 DAWdex → 电梯上行（楼层数字跳动，正好掩盖 openDAW 工程加载）→ 门开 = 进入白天棚内 → 基础 Loop 响起。游戏感从第一秒开始，且零额外成本（静态图 + 数字跳动）。

### 9.5 弹幕特色定位（反转 Prompt-to-Song）

常规 AI 音乐：一个输入框 → 等待 → 一首歌。DAWdex 反转它：

- **输入不是一次性提交，是持续的弹幕流**——参与感来自"和一群人一起喊"，不是"填写需求"；
- **反馈不是进度条，是角色和房间的反应**——Agent 附和弹幕、乐手入场、灯光变化；
- **产出不是成品音频，是看得见生长的循环**——每一条弹幕都能指认"它改变了哪一轨"。

弹幕是输入方式、氛围系统、叙事载体三合一。Agent 附和必须遵守同一原则：**弹幕内容从结构化指令派生**（FR-03），不是表演性文案。

### 9.6 三层边界（我只负责 UI 与舞台层）

对应 `repo/docs/division-of-labor.md` 成员 A 的职责，UI/舞台层与其他两层的契约：

**从 openDAW 引擎层消费（只读 + 受限写）：**

| 契约 | 内容 |
|---|---|
| `TransportState` | bpm / key / bar / 循环位置 / 循环边界事件回调 |

### 11.2 游戏化系统（v2.2 重做版）

1. **巡棚系统（频道 = 房间）**：点击角色名/角色弹幕 → 镜头切入对应房间；房间 `REC` 灯牌亮 = 该房正在发声，观众不看 UI 徽章也能读懂工程状态。MVP 固定控制室机位，P1 开放房间跳转（雪花噪声转场）。
2. **入场系统**：新轨加入三步——`queued`：目标房间灯牌开始闪烁 → 循环边界到达：`TrackAudibleChanged` → 角色 sprite 进入站位、灯牌转常亮 → 下一拍开始演奏动画。**灯牌闪烁 → 常亮就是"等待循环边界"的全部解释**，零文字。
3. **弹幕河 + 附和（见 §11.3）**。
4. **干预物理化（FR-09）**：「换乐器」= 点房间里的另一把琴（吉他棚三把、键盘房四台）；「更有力量/更轻松」= 踏板或角色头顶 ±；「撤销」= 控制室调音台旁的撤回钮。操作不只发命令，**房间物件给出物理反馈**（被选的琴发光）。

### 11.3 弹幕定位（v2.2）

- **主战场在 Lounge 与当前房间上半部**，不遮角色脸；真人白字、AI 乐迷灰字带徽标（从沙发区"发出"）、系统消息底部短暂停留。
- **Agent 附和带方向感**：制作人附和从控制室方向、乐手附和自己房间方向发出，角色色 + 身份徽标；内容一律来自事件的 `echo` 字段（B 产出），与结构化指令同源。
- **升格时刻**：被采纳弹幕 → 当前房间灯牌大标题（11s 滚动），同时进证据抽屉。
- **反转 Prompt-to-Song 的完整表述**：输入 = 持续弹幕流；反馈 = 房间与角色的物理反应；产出 = 看得见逐轨生长的循环；证据 = 点任何回执可展开结构化指令。

### 11.4 我的边界（v2.2，契约已存在）

UI/舞台层只消费 `UiEvent` 七个事件、只发出 `UiCommand` 两个命令（`contracts/ui-contract.ts`）。三个合法本地状态（不算造假）：① 循环进度条本地时钟（`TransportChanged` 校准）；② 电梯加载（boot 状态）；③ 弹幕输入即时回显（以 `DanmakuReceived` 为最终凭据）。**其余任何视觉必须能指出自己的事件源。**

**叙事一句话**：你面对的是一台正在直播 DAWdex 录音棚的监视器——屏幕里是大楼，屏幕外是你的操作台。弹幕输入条的本质是**对着演播室喊话的对讲机**。

### 12.2 三区信息架构

| 区 | 位置 | 内容 | 风格 |
|---|---|---|---|
| **A · 屏幕区** | bezel 内 | 房间画面、弹幕河、角色 sprite、REC 灯牌、循环进度、灯牌升格 | 像素风只在 A 区 |
| **B · 控制台区** | 壳下部 | 弹幕输入条（唯一主输入，永远常显）+ FR-09 六操作行 | Kimi 风白卡 |
| **C · 抽屉区** | 壳底部 | 乐队会议 / 工作回执 / 结构化指令 / plan 审批，默认收起 | Kimi 风 |

**顶部壳**：品牌 `DAWDEX` + `ON AIR` 灯 + Mock 重播钮。**顶部不放时钟**——权威时钟只住在屏幕内的 REC 监视器里，避免同一信息两个家。

### 12.3 壳上"硬件"（仅三个，全部绑真实数据）

| 控件 | 功能 | 数据源 |
|---|---|---|
| `ON AIR` 灯 | 会话播放状态（亮/呼吸/灭） | `TransportChanged.isPlaying` |
| 频道旋钮（P1） | 房间切换：Lounge / 鼓棚 / 吉他贝斯棚 / 键盘阁楼 / 控制室 | 巡棚系统路由 |
| 电源键 | play / pause | transport 控制（与 C 对齐命令通道后启用） |

**壳上控件遵守与屏幕内相同的规则：必须绑定真实数据源，不得装饰化。** 除此之外壳上不再增加任何"硬件"——旋钮越多，越像玩具而不是产品。

### 12.4 材质与色彩

- 页面壳：暖白 `#f7f5f2` + 发丝线 `#e5e2dc`（Kimi 风）
- bezel：深棕黑 `#26221e`、22px 圆角（CRT 弧度）、内侧 2px 高光 + 外投影（MVP 已实现）
- B/C 区控件：白卡 + 黑色主按钮，圆角 10–14px，**零像素元素**
- 壳屏交界：bezel 即全部过渡，不加额外装饰条

### 12.5 壳/屏边界五条铁律

1. **像素风只在屏幕内**，壳上零像素元素（违反即变成廉价主题皮肤）；
2. **弹幕只在屏幕内飞**，输入框永远在壳上常显（互动不被画面遮挡）；
3. 屏幕内可点击的都是**房间物件**（§11.1），壳上可点击的都是**控制台**——用户永远知道自己在点"世界"还是点"界面"；
4. **加载时电梯只占屏幕区**，壳（品牌 + bezel）保持不动，保证品牌连续性；
5. **投屏演示模式**：隐藏 C 区、缩小 B 区、A 区最大化，一档切换。

## 13. v2.3 · 冲突裁决与方向修正（2026-07-25，回应 Codex 总结文档 §16）

### 13.1 四个冲突的裁决

Codex 总结文档 §16 列了四个冲突，裁决如下：

**① Loop vs 完整歌曲（真冲突，唯一的一个）**
房间的语义是"乐器/角色"，编码不了歌曲的时间结构。"第二段主歌"没有房间可住。解法：
- 控制室场景增加**编曲白板**（pinboard）：Intro / Verse / Chorus 卡片钉在板上，选中 Section = 卡片高亮，锁定 = 钉图钉。Song Map 必须长在世界里，不得做成壳上的 timeline 条（违反壳屏铁律）。
- 契约扩展为**纯加法**：现有 7 事件是"循环层"，完整歌曲再加"歌曲层"事件（`BlueprintChanged` / `SectionChanged` / `SectionLocked` 等），v0.1 冻结后只做增量版本，不重设计。

**② 弹幕范围（范式遗物，建议修订 PR #3）**
PR #3 的"全应用弹幕"写于旧范式（openDAW + 覆盖层）。新范式下屏幕就是应用，"只在屏幕内"是更严格的世界观：弹幕是喊进演播室的话，证据抽屉是操作台的文件。**正式规则：弹幕的家是屏幕世界；专业视图展开时弹幕不覆盖它。** PR #3 相应条款应修订。

**③ 唯一输入（已解决）**
正式表述：**弹幕是唯一常驻自然语言输入；房间物件和六种干预按钮是快速操作捷径。**

**④ 替代 DAW 的边界（已被三区架构解决）**
空间化前端为默认产品；openDAW 为底层执行器 + 可展开的专业模式；C 区抽屉即证据层的家。代码中已落地，不再是冲突。

### 13.2 前端的本质：因果翻译层

前端不是 Music State Translation Layer 的全部——它独有的价值是**因果翻译**：

> 用户说了一句话 → 世界因此改变，且因果链全程可见（弹幕 → 采纳 → 升格 → 角色起身 → 循环边界 → 真实发声 → 可撤销）。

生成式音乐工具给用户"结果"，DAWdex 给用户"后果"。因此**所有视觉必须绑真实事件不是工程洁癖，而是体验的护城河**：伪造一次演奏动画，因果契约破产，"指挥乐队"塌成"看动画片"。演示策略由此确定：

- **好结果**：联调完成，↻ 播 B/C 真实事件，performing 与 openDAW 发声严格一致
- **兜底**：现场链路出问题，一键 ↻ 回 Mock 时间线（与真实接口同一 emit 签名，叙事不变）

### 13.3 舞台皮肤：夜晚唯一 + 循环视频（决策 2026-07-25）

- **废除昼夜切换**：白天排练模式取消，夜晚是唯一舞台皮肤。`studio_day.jpg` 退役。
- **舞台背景升级为 10 秒循环视频**（`studio_night_loop.mp4`，1920×1080）：混音台通道灯跳动、监视器时间码走字、节拍器摆动——场景自己"活"了。这些已动画的物件是后续热点绑定的天然对接点。
- `studio_night.jpg` 保留为 poster/降级静帧。
- 光照驱动 energyChange 的设想保留，但实现对象改为视频的后续变体（如演出高潮版 loop），不再是昼夜两张静态图。

### 13.4 角色方向：保留，但重做（决策 2026-07-25）

旧 V3 Q 版立绘与场景画风格格不入（头身比/描边/渲染/像素颗粒/视角/光影六项断层，见 §13.5），正式降级为占位。新方向：

1. **人物是状态机的人格化，不是装饰性立绘**——场景尺度的小人，不是画面中央的主角
2. **人物不演奏乐器**——乐器属于房间（轨道的锚点），人物只表现状态；避开 AI 生成最高危的"手+乐器交互"
3. **基于场景图重做**——生成时以房间图为风格参考（图生图/风格迁移），透视、光源、像素颗粒从房间里长出来，不用文字凭空描述
4. **Lounge 是角色的家**——waiting = 在 Lounge 或不在场；queued = 站到乐器旁；performing = 轨道确认发声后随节奏动作；入场/退场走房间切换
5. 跨房间一致性：固定参考图 + 逐房校尺，同一角色在每个房间必须是同一个人、同一尺度逻辑
6. Demo 档动画：PNG + CSS（出现/消失 + 节拍轻晃）；走位动画演示后再做

### 13.5 角色 vs 场景断层诊断（存档）

| 维度 | 旧角色立绘 | 场景（基准） |
|---|---|---|

| 描边 | 粗黑轮廓线 | 无描边，色块分界 |
