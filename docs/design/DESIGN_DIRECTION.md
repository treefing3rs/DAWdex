# DAWdex 设计方向 v2 · Kimi 风 × 伪 8-bit 演播机

> 版本：v2.1 · 2026-07-24（v1 三方案对比见 `DESIGN_BRIEFS.md`；v2.1 融合用户自制场景，确定"游戏化 DAW"形态）
> 目标仓库：<https://github.com/treefing3rs/DAWdex>（本地副本 `repo/`）

---

## 1. 方向定义

**一句话：把 DAWdex 做成一台"复古演播机"——Kimi 式的克制外壳 + 伪 8-bit 像素的屏幕内容，屏幕里的每一个像素都是真实状态。**

两条血脉的融合方式：

| 血脉 | 负责什么 | 具体表现 |
|---|---|---|
| **Kimi 风格** | 外壳与交互层 | 大面积留白、细发丝边框、克制的圆角、系统字体、低饱和中性色；输入框、按钮、面板的呼吸感 |
| **伪 8-bit 像素** | 屏幕内容层 | 角色、舞台、状态灯、跑马灯全部像素化；刻意低帧率（8–12fps）动画；像素进度条 |

**关键原则：外壳是现代产品，屏幕里是复古现场。** 用户摸到的是 Kimi 的顺滑，看到的是游戏机的灵魂。两层不混淆——像素风绝不蔓延到输入框和按钮上，否则变成廉价主题皮肤。

### 复古外壳形态（三选一，建议 TV）

1. **复古电视机（建议）**：圆角 CRT 机身框住舞台区，右上角一枚像素 `ON AIR` 灯 + 频道旋钮（旋钮即角色切换），底部扬声器格栅恰好是弹幕输入区的位置。
2. **掌上游戏机**：舞台是屏幕，下方十字键/AB 键映射为 FR-09 的六个操作（保留/更有力/更轻松/换乐器/重新生成/撤销）。交互映射最妙，但屏幕占比小。
3. **监视器/显示屏**：最接近 Brief A 的终端气质，最稳妥但记忆点最弱。

## 2. 屏幕内容 = 真实状态（核心设计约束）

屏幕不是装饰动画，**每个视觉元素绑定一个真实数据源**：

| 屏幕元素 | 数据源 | 交互 |
|---|---|---|
| 角色 loop 动画 | openDAW 对应轨道是否发声（PRD：角色只按轨道有声/无声切换演奏状态） | 点击角色 → 定位/选中对应轨道 |
| 角色头顶状态灯 | Agent 状态机：等待/思考/准备/演奏/失败 | 点击 → 展开该角色最近一条工作回执 |
| 像素循环进度条 | 工程权威 BPM + 循环边界（FR-06） | 无（纯指示） |
| 跑马灯大标题 | 被制作人采纳的弹幕原文 | 悬停暂停 |
| 雪花噪点 | 模型失败 / 校验未过 / 本地回退触发 | 点击进入事件日志 |
| 底部弹幕流 | 真弹幕 + Agent 附和 + AI 乐迷 + 系统消息 | 点击弹幕 → 高亮它影响的轨道 |

**说一套做一套在这个界面里没有藏身之地**——角色不动就是轨道没响，雪花一出现就是真的出错了。

## 4. 弹幕系统（核心亮点）

参考 B站弹幕，但比 B站多一层：**Agent 也是弹幕参与者**。

### 4.1 弹幕类型与视觉区分

| 类型 | 样式 | 说明 |
|---|---|---|
| 真人观众 | 白字 | 默认弹幕 |
| **制作人 Agent** | 青色描边 + `🎛 制作人` 小徽标 | 裁决、附和、追问 |
| **乐手 Agent** | 角色色描边 + 角色小徽标 | "鼓手收到，四拍底鼓安排上了" |
| AI 乐迷 | 灰字 + `AI 乐迷` 徽标（PRD 强制标记） | 气氛组 |
| 系统 | 居中底部短暂停留，不滚动 | "新轨将在下一循环进入" |

### 4.2 弹幕只活在屏幕里

弹幕层 `absolute` 覆盖在**电视屏幕内部**（不是整个页面），`pointer-events: none` 穿透；多轨道分层速度；长文本截断；危险内容过滤。这样弹幕永远不与外壳控件争抢，视觉上也像"节目的一部分"。

### 4.3 Agent 附和机制

- 用户发送弹幕后，**原文立即上屏飘过**（零延迟反馈）。
- 制作人 Agent 的附和/回复**也以弹幕形式发出**（而不是只在对话框里）——观众看到自己的弹幕和 Agent 的回应在同一条河里漂，这是"乐队真的在听你说话"的最强证据。
- 采纳的弹幕升格为**跑马灯大标题**；被拒绝的弹幕正常飘过，制作人弹幕简短说明原因。
- 附带规则：Agent 弹幕必须可溯源——点击 Agent 弹幕展开对应回执/指令。

### 5.2 每角色需要 3 组素材

| 素材 | 内容 | 用途 |
|---|---|---|
| **待机 idle** | 角色安静站着/坐着，轻微呼吸摆动 | 轨道未加入或未发声 |
| **演奏 playing** | 完整演奏动作 loop（打鼓/拨弦/按键/扫弦/推推子） | 轨道发声中 |
| **准备 ready**（可省） | 乐器上手、看向制作人 | 任务已领取，等待循环边界 |

失败态不需要素材——用**雪花噪点转场**覆盖该角色区域即可。

### 5.3 生产步骤

1. **图片（已完成第一轮）**：image_generation 生成单帧立绘。如需更连贯的动画，应补生成「同角色 2–4 个关键姿势」（用 `image-to-url` + `--reference-image` 保持角色一致性）。
2. **Loop 视频**：以立绘为参考帧做图生视频（img2video），要求：
   - 时长 2–4 秒，**首尾帧可无缝循环**（循环点对齐 128BPM 的一拍或半拍 ≈ 0.47s/0.94s 的整数倍）；
   - 动作幅度小而密（手腕、头部、身体重心），不要做位移大的动作；
   - 保持像素风与角色色，透明/纯色底便于抠像；
   - 每个角色至少 idle、playing 两段。
3. **Codex 产品化**：视频到货后交给 Codex 做工程化，验收标准：
   - 转封装为 Web 友好格式（循环 `<video muted loop playsinline>` 或 WebM/APNG），`image-rendering: pixelated` 保持像素锐利；
   - 封装为 `PerformerSprite` 组件：props = `{role, state, accentColor}`，按状态切换播放源，切换时用 100ms 雪花噪声遮罩掩盖接缝；
   - 状态机与 openDAW 轨道发声事件对接（`playing ⇄ idle`），与 Agent 事件对接（`thinking/ready` 显示状态灯）；
   - 失败/降级路径：视频加载失败时回退为静态 PNG + CSS 抖动动画，保证 Demo 不翻车。

### 5.4 素材规格

- 画布：2:3 竖版，角色占高约 80%，透明 PNG/WebM(VP9 alpha)；
- 舞台上显示高度约 160–220px，源素材 1024×1536 足够；
- 像素颗粒度：角色边缘可见明确像素块，禁止平滑渐变糊边。

## 9. v2.1 · 场景融合：房间即工程（游戏化 DAW）

### 9.1 已有场景素材与用途

用户自制 4 张像素场景（`assets/scenes/`），全部位于外壳屏幕内部：

| 素材 | 内容 | 设计用途 |
|---|---|---|
| `...meutpo...png` | 控制室夜景：大调音台、三联 DAW 监视器、暖灯 | **主场景·演出态**。房间内嵌界面（diegetic UI）的主战场 |
| `...mfohwp...png` | 录音棚夜景：设备架、REC 监视器、沙发上吉他、暖灯 | **主场景·日常态/候补主场景** |
| `...vicbn2...png` | 同一录音棚白天版 | **状态皮肤**：白天 = 等待/排练；夜晚暖灯 = 演出中/作品完成 |
| `...rclp3n...png` | 「DAY 9」电梯间，背吉他的人 | **加载/开场画面**：进棚 = 上电梯，游戏感的第一步 |

判断：方向完全成立，而且这四张图里藏着这套设计最关键的东西——**场景自带"屏幕"和"控制台"**。REC 监视器、三联 DAW 显示器、调音台通道、音箱，这些不是装饰，它们是天然的"界面内嵌界面"锚点。

### 9.2 核心手法：Diegetic UI（界面内嵌界面）

游戏沉浸感的第一原则：UI 画在世界里，而不是浮在世界上面。DAWdex 的每个真实数据都找一个场景内的"宿主"：

| 场景内锚点 | 绑定的真实数据 | 呈现方式 |
|---|---|---|
| REC 监视器 | 权威时钟：BPM / 调性 / BAR / 循环进度 | 叠加像素字滚动屏，`01:23:45` 换成实时走带 |
| 调音台通道条 | openDAW 每轨电平 | 通道灯随电平跳动（CSS/canvas 热点） |
| 三联 DAW 显示器 | openDAW 轨道概览（Region 色块 = 角色色） | 缩小版"工程视图"；点击放大为抽屉 |
| 沙发上的吉他 | 吉他手轨道未加入 | 乐器静置；轨道加入时角色入场拿起乐器 |
| 音箱 / 设备架灯 | 轨道发声状态 | 发声时喇叭微振、设备灯亮 |
| 房间灯牌 / 墙面 | 被采纳弹幕原文 | 升格为房间内的像素灯牌字幕 |
| 吊灯 / 整体光照 | 会话能量（energyChange） | 能量越高灯越暖越亮；昼夜皮肤切换 |
| 房间本身 | 模型失败 / 回退 | 灯泡闪烁 + 雪花噪点掠过屏幕 |

**实施要点：沉浸感来自"少量精动的热点"，不是整图动画。** 场景图保持静态，只在锚点位置叠加小尺寸发光/跳动元素（绝对定位 + CSS 动画 + 可选小 canvas）。整图不做视差、不做缩放——像素图一动就糊。

### 9.3 游戏化系统（全部绑定真实数据，无一装饰）

1. **入场系统**：新轨不是"出现"，是角色**走进房间**。循环边界到达 → 房间灯一闪 → 角色从侧门/电梯入位 → 乐器上手 → 下一拍开始发声。这是 Flow 5 的游戏化翻译，也是 Demo 最爽的瞬间。
2. **状态灯系统**：角色头顶像素状态灯（等待/思考/准备/演奏/失败），与轨道发声严格同步，点击展开该角色回执。
3. **弹幕河**：弹幕在房间上半部飘过（场景内，不遮角色脸），五种身份样式同 v2 §4；Agent 附和弹幕是互动感的核心填充。
4. **升格时刻**：弹幕被采纳 → 原文短暂成为房间灯牌大标题 + 制作人弹幕宣布理由。
5. **昼夜皮肤**：开场白天（排练感）→ 首条弹幕被采纳后渐入夜景暖灯（演出感）→ 作品完成循环时满灯。状态迁移本身成为叙事。

### 9.4 开场：上楼进棚

「DAY 9」电梯图直接作为加载画面：打开 DAWdex → 电梯上行（楼层数字跳动，正好掩盖 openDAW 工程加载）→ 门开 = 进入白天棚内 → 基础 Loop 响起。游戏感从第一秒开始，且零额外成本（静态图 + 数字跳动）。

### 9.5 弹幕特色定位（反转 Prompt-to-Song）

常规 AI 音乐：一个输入框 → 等待 → 一首歌。DAWdex 反转它：

- **输入不是一次性提交，是持续的弹幕流**——参与感来自"和一群人一起喊"，不是"填写需求"；
- **反馈不是进度条，是角色和房间的反应**——Agent 附和弹幕、乐手入场、灯光变化；
- **产出不是成品音频，是看得见生长的循环**——每一条弹幕都能指认"它改变了哪一轨"。

弹幕是输入方式、氛围系统、叙事载体三合一。Agent 附和必须遵守同一原则：**弹幕内容从结构化指令派生**（FR-03），不是表演性文案。

### 9.6 三层边界（我只负责 UI 与舞台层）

对应 `repo/docs/division-of-labor.md` 成员 A 的职责，UI/舞台层与其他两层的契约：

**从 openDAW 引擎层消费（只读 + 受限写）：**

| 契约 | 内容 |
|---|---|
| `TransportState` | bpm / key / bar / 循环位置 / 循环边界事件回调 |
| `TrackRoster` | 轨道列表：角色、乐器、颜色、是否发声、电平 |
| `TrackAudibleEvent` | 轨道发声/静音 → 驱动角色演奏/待机 |
| `UndoResult` | 撤销成功/失败 |

**从 Agent API 层消费：**

| 契约 | 内容 |

| `AgentUiEvent` | 裁决结果（采纳/拒绝 + 理由 + 置信度）、附和弹幕文本 |

| `MusicBrief` | 全局约束（可折叠展示） |

**向上暴露：**

| 契约 | 内容 |
|---|---|
| `DanmakuSubmit` | 用户弹幕原文（唯一输入） |
| `UserIntervention` | FR-09 六操作：保留 / 更有力 / 更轻松 / 换乐器 / 重新生成 / 撤销 |

**本层不做**：解析模型自由文本、保存 API Key、决定 MIDI 音符、直接改 openDAW 工程。建议把上表落成一份 `ui-contract.ts` 类型文件，三方对着类型开发，互不阻塞。

### 9.7 场景素材缺口

- ⬜ 乐手站位：现有场景是空房间，需要确认角色 sprite 在房间中的站位坐标（建议：控制室夜景中调音台后 = 制作人；棚内夜景中鼓手/贝斯/键盘/吉他各就位）
- ⬜ 鼓组/键盘道具：场景里有吉他和话筒，没有鼓组和键盘——要么补生成带乐器的场景版本，要么乐器随角色 sprite 自带
- ⬜ 门/电梯口：角色入场的通道位置，需要在场景图上标定
- ⬜ 弹幕灯牌位：墙面空白区预留
