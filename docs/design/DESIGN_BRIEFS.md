## 0. 调研结论（设计的前提）

### 0.1 openDAW 给了我们什么、缺什么

openDAW 的界面是标准 DAW 布局：中央时间轴 + 左侧素材浏览器 + 底部设备面板（近似 Ableton Live / Bitwig），面向“用过 DAW 的人”。它解决的是**引擎与工程**，不解决“音乐小白 10 秒内看懂”。

对 DAWdex 的结论：

- openDAW 的时间轴**可以保留但必须退居二线**——它是“证据层”（让用户看见 MIDI 真的被写入），不是主交互层。
- 主界面必须重构为 PRD 的叙事：**舞台（虚拟乐手）→ 弹幕（输入）→ 角色对话（编译过程可见）→ 逐轨生长（反馈）**。
- 专业 DAW 元素（音轨颜色、Region、循环边界）反而可以借来作为视觉语言：轨道色 = 角色色，循环边界 = 舞台节拍点。

### 0.2 Mureka 可借鉴与不可借鉴的

Mureka 的设计特征：深色现代主题、极低的进入门槛（Easy Mode 一句话生成）、生成中即可流式试听、Create / Library 双区 dashboard、以及 Studio 多轨编辑。

可借鉴：

- **单一大输入框 + 一个主行动按钮**的心智，对应 DAWdex 的弹幕输入。
- **生成过程可听可见**（流式）——对应“轨道在循环边界逐条加入”。
- Easy / Custom 双模式 → 对应 DAWdex 的“观众模式 / 制作人模式（可折叠的专业视图）”。

不可借鉴：

- Mureka 是“一次性生成成品”的工具感界面；DAWdex 的核心卖点是**过程**（编译可见、角色在场、逐轨生长）。界面必须是“现场”，不是“表单”。
- Mureka 的列表 + 卡片结构撑不起弹幕、舞台、时间轴三者同屏。

### 0.3 设计原则（三个 brief 共同遵守）

1. **舞台优先**：打开页面 3 秒内看到“乐队 + 正在循环的音乐”，不是 DAW 时间轴。
2. **编译可见**：观众看到“人话 → 结构化指令”的翻译过程，JSON 默认折叠但永远可展开。
3. **轨道即角色**：每条轨有固定角色、固定颜色、固定位置；角色状态（等待/思考/准备/演奏/失败）与轨道发声严格同步。
4. **弹幕不挡操作**：弹幕层 pointer-events 穿透，输入与批准永远可达。
5. **一个权威时钟**：BPM / 调性 / 循环长度全局可见，是界面的“心率”。

## Brief A · 指挥台（Mission Control）

**一句话：把 DAWdex 做成一个“音乐制作指挥中心”——弹幕是情报流，制作人是值班主任，乐手是执行单元。**

### 概念

观众不是在看演出，而是在**监制**。界面气质接近情报/金融终端：高信息密度、每个状态都有指示灯、每条决策都有回执编号。黑客松评委能一眼看到“这不是聊天玩具，是一条真实的数据管线”。

### 首屏布局

```
┌────────────────────────────────────────────────────────────┐
│ DAWDEX ● LIVE   BPM 128 · A minor · 4 bars · LOOP 03  ▶ ⏸ │ ← 顶部状态栏（权威时钟）
├──────────┬──────────────────────────────┬──────────────────┤
│ 轨道/角色 │        舞台 · 环形循环         │   制作人·会议     │
│ 面板 280px│   （乐手站位 + 循环进度环）     │   面板 380px     │
│          │                              │                  │
│ 🥁 鼓手   │      （弹幕层全屏飘过）        │  💬 角色对话流    │
│ 🎸 贝斯   │                              │  ▸ 可折叠 JSON    │
│ 🎹 键盘   │                              │  ✓ 采纳/✗ 拒绝    │
│ 🎤 主奏   │                              │                  │
├──────────┴──────────────────────────────┴──────────────────┤
│ ▸ 时间轴（默认收起为一条细带，点击展开 openDAW 轨道证据层）      │
└────────────────────────────────────────────────────────────┘
                  底部固定：弹幕输入框（全局焦点 / 键）
```

### 色彩

深色智能终端色系，三档主题用 CSS 变量整体切换：

| 角色 | 色值 | 语义 |
|---|---|---|
| 背景 / 面板 | `#050810` / `#0c1220` | 深空黑蓝 |
| 边框 | `#1a2540` | 1px 发丝线 |
| 系统 LIVE / 制作人 | `#22d3ee` 青 | 活跃、广播中 |
| 鼓手 | `#fbbf24` 琥珀 | 节奏、驱动 |
| 贝斯手 | `#34d399` 薄荷绿 | 低频、稳定 |
| 键盘手 | `#e879f9` 品红 | 和声 |
| 主奏 | `#f87171` 红 | 焦点旋律 |
| 失败 / 回退 | `#f87171` + 斜纹 | 校验未过 |

### 字体

- UI 骨架、数据、参数：**JetBrains Mono**（300–700），标签小号大写 + 宽字距（0.08–0.22em）。
- 角色对话、弹幕正文：**Inter**（400–800）+ 系统中文字体兜底（`"PingFang SC", "Microsoft YaHei"`）。
- 层级靠字号（9–32px）× 字重 × 字距建立，不靠颜色。

### 动效

- 常驻环境动画：LIVE 呼吸点（1.4s ease-in-out）、顶部状态栏循环进度环、被采纳弹幕的 ticker 横幅（48s 线性滚动，hover 暂停）。
- 角色状态切换：雷达节点式指示器——外圈发光环 + 中心点，等待=暗、思考=旋转扫描（4.2s）、准备=闪烁、演奏=常亮呼吸、失败=红闪。
- 新轨进入：循环边界到达瞬间，左面板轨道行从左缘插入一条 3px 角色色 accent，同时舞台角色亮起。
- 所有 hover 过渡 0.15s ease；折叠区 0.42s cubic-bezier；尊重 `prefers-reduced-motion`。

### 关键组件

- **裁决卡（Verdict Card）**：被采纳弹幕 → 左侧 3px 青色 accent + 置信度条 + “采纳理由”一句话 + 展开查看结构化 Brief。
- **工作回执（Receipt）**：角色消息固定结构「将做什么 / 听起来会怎样 / 查看指令 ▸」，点击定位左面板对应轨道。
- **意图编译流水线条**：8 个节点（输入→纠错→聚类→裁决→Brief→角色任务→执行→校验）横向排布在右面板顶部，当前节点发光，失败节点变红并显示回退标记。
- **弹幕层**：全屏 absolute 覆盖，多轨道不同速度，真人/AI 乐迷/系统三种徽标，长文本截断，危险内容直接不入轨。

### 与 PRD 的映射

Flow 2 的“聚类/评分”天然适合终端气质；90 秒 Demo 的 18–45 秒（编译与交接）在本方案中最有说服力——评委能看到管线在跑。

### 风险

- 气质偏“工程师评审友好”，对“音乐小白观众”的亲和力是三者中最弱的；弹幕文化感弱。
- 信息密度高，Demo 投屏时需要一档“演示模式”放大字号。

## Brief B · 演播厅（Broadcast Studio）

**一句话：把整个产品做成一台“正在直播的电视台”——每个角色是一个频道，弹幕是信号，换轨就是切台。**

### 概念

DAWdex 的核心输入是弹幕——那就让界面**本身就是弹幕文化的母语**：CRT 显像管、电传打字（teletext）字体质感、频道指示灯、节目跑马灯。它直接把“B 站直播”的熟悉感搬进编曲现场，是三个方案中**观众 10 秒理解成本最低**的。

### 首屏布局

```
┌────────────────────────────────────────────────────────────┐
│ [CH1 鼓] [CH2 贝斯] [CH3 键盘] [CH4 主奏] [CH5 总控]  ● ON AIR │
├──────────────────────────────────────────────┬─────────────┤
│                                              │  侧栏 24rem  │
│            主画面（当前频道/全景舞台）          │  · 节目单     │
│       像素化大标题跑马灯 + 角色演出画面          │  · 角色对话    │
│       底部: BPM · KEY · 循环进度像素条          │  · 结构化指令  │
│                                              │  · 操作按钮组  │
│            （弹幕层全屏覆盖，像素字体）          │  · 设置       │
├──────────────────────────────────────────────┴─────────────┤
│ ▶ 输入弹幕：____________________  [发送]   方向键切台 · F 全屏  │
└────────────────────────────────────────────────────────────┘
```

- 频道条五等分，未激活 25% 透明度，激活 100% + 频道色像素脉冲点。
- “全景舞台”是 CH0 隐藏频道：所有角色同台（默认首页）。

### 色彩

纯黑 `#000000` 打底，每个角色一个频道色（平涂色块，无渐变无阴影）：

| 频道 | 色值 |
|---|---|
| 鼓手 | `#f5e6b8` 暖奶油 |
| 贝斯手 | 灰绿（muted green） |
| 键盘手 | 去饱和紫 |
| 主奏 | 焦橙 |
| 总控/系统 | 淡黄 |
| ON AIR / 活跃指示 | `#24eb4f` 荧光绿，2s 脉冲 |

文字一律纯白 `#ffffff`；唯一的高亮给“正在发声”这件事。

### 字体

- 频道标题、BPM、循环计数：**像素 SVG 字体**（块状 8-bit 路径，`image-rendering: pixelated`）。
- 弹幕、对话正文：iA Writer Duo 风格的可变等宽 + 中文字体兜底；中文弹幕用系统黑体即可，不做伪斜体。
- 节目单、时间戳：小号 grotesque 无衬线。

### 动效（本方案的灵魂）

- **频道切换 = 切台噪声**：双 canvas 像素噪声系统——离屏 canvas 以低分辨率生成噪声瓦片，主 canvas 以随机 0°/90°/180°/270° 旋转拼贴；**刻意锁 12fps**（用 `setTimeout(600/fps)` 而非 rAF）制造模拟信号的顿挫感；切台瞬间配一声 channel-change 短音效。角色轨加入时同样用“频道接入”噪声转场——观众看到的是“信号接通了”。
- **弹幕 = 跑马灯**：CSS `translate3d(-100%,0,0)` 无缝循环，时长用 CSS 变量按文本长度计算；多轨分层速度；hover 暂停。
- **循环边界**：主画面底部的像素进度条走满一格，全画面做一次 2px 像素抖动——“循环点”成为可感知的舞台节拍。
- 按钮:active 收缩至 0.95；图标按钮一律 1:1 方形、零圆角。

### 关键组件

- **频道徽章**：`[CH2]` 样式 + 荧光绿脉冲点，即角色状态机的外显（等待=灰、思考=扫描线、准备=闪烁、演奏=常亮、失败=雪花噪点定格）。
- **节目单（侧栏顶部）**：当前 Music Brief 以电视节目单排版——“20:00 鼓手入场 · 四拍底鼓 + 十六分踩镲”。
- **回执 = 电报条**：角色回执用 teletext 风格单行滚动条呈现，展开后才是完整结构化指令。
- **像素标题跑马灯**：被采纳弹幕会短暂成为主画面大标题（“像最终 Boss 一样炸！”），这是“观众意见被采纳”的 90 秒 Demo 高光时刻。

### 与 PRD 的映射

FR-01 全屏弹幕层在此方案中是**原生公民**而非叠加层；Flow 5“轨道在循环边界进入”被翻译成“频道接入”，叙事零解释成本；AI 乐迷标记天然契合“虚拟观众席”的电视台设定。

### 风险

- 像素/CRT 风格完成度要求高，做不好会显得廉价；需要真做双 canvas 噪声，不能用贴图糊弄。
- 专业感弱于 Brief A，若评委偏技术向，需要用侧栏的结构化指令区补回“管线可见”的证据。
- 像素中文字体没有现成方案，中文大标题需用点阵化处理或退回系统黑体描边。

## Brief C · 环形舞台（Loop Stage）

**一句话：删光所有面板，只剩一个全屏画布——音符沿着无限环流动，角色站在环上，作品是一条看得见的循环。**

### 概念

DAWdex 的音乐不是时间轴上的线性工程，而是**一个不断循环生长的环**。把循环本身做成主视觉：一条 ∞ 形（lemniscate）轨道贯穿全屏，四个声部的音符沿轨道流动，播放到哪里哪里亮。虚拟乐手站在轨道节点上，自己的音符经过时开始演奏动画。这是三者中**最具艺术性和记忆点**的方案，也是“一句话讲清产品”的最佳演示形态。

### 首屏布局

```
┌────────────────────────────────────────────────────────────┐
│ DAWDEX                              BPM 128 · A minor      │ ← 文字悬浮四角，mix-blend-mode: difference
│                                                            │
│              ╭─────────────────────╮                       │
│             ╱   音符流（角色色）     ╲                      │
│            │   🥁      ∞      🎹   │   ← 全屏 canvas ≈90% │
│             ╲   🎸          🎤    ╱     乐手立于环节点       │
│              ╰─────────────────────╯                       │
│                                                            │
│ ▶ 输入弹幕________                          ⓘ 展开指令      │
└────────────────────────────────────────────────────────────┘
```

- 无侧栏、无面板。四角悬浮纯文字 UI：左上产品名，右上权威时钟，左下弹幕输入，右下“信息/指令”入口。
- 弹幕仍全屏飘过，但降透明度、置于音符流之下一层，不抢主体。
- 角色对话以**气泡**形式出现在乐手头顶，5 秒自动收缩为一个角色色小圆点，点开重看。

### 色彩

两条路线任选（都需要快速出原型验证）：

- **C-1 白昼乐谱**：暖白 `#f4f4f4` 底，音符与文字纯黑 `#000000`，四个角色仅靠**音符形状/运动**区分（鼓=方块、贝斯=实心圆、键盘=连线、主奏=星形），零彩色。最克制、最艺术。
- **C-2 紫夜现场**：深紫 `#2C1338` 底，音符用粉 `#E57CD8`、暖奶油 `#FCE5D8`、薄荷绿、琥珀区分角色；悬浮文字用奶油色。更“现场演出”，与弹幕文化兼容更好。

### 字体

- 标题/作品名：一把有戏剧性的衬线斜体（拉丁）+ 中文宋体（`"Songti SC"`）——“DAWDEX presents ∞ Loop No.1”。
- UI 标签：中性瑞士无衬线（Basel Grotesk 气质）+ 系统中文黑体。
- 若实现音符渲染，可直接引入 SMuFL 兼容记谱字体（如 Bravura）画真实音符 glyph，而不是圆点。

### 动效

- **音符流**：canvas（Paper.js 或原生 2D）驱动，音符从环的一侧进入、沿曲线路径行进、离开；进入侧的角色色淡入，离开侧淡出。
- **声画同步**：每个音符事件带时间戳，播放光标经过时该音符做一次 100–200ms 的缩放脉冲（+颜色反转 via blend mode），同时触发对应乐手的演奏帧。
- **新轨加入**：循环边界到达时，新声部的第一组音符从环外“飞入”轨道——观众亲眼看到“这一层长出来了”。
- canvas 设 `pointer-events: none`，文字可直接选择；glyph 缓存为矢量路径，rAF 循环。

### 关键组件

- **无限环**：全屏唯一主体，lemniscate 路径参数化生成，环的粗细随总能量（energy 参数）微变。
- **乐手立像**：MVP 用极简几何小人（SVG 骨骼 + 两种姿态：待机/演奏），不做复杂立绘；状态机同三方案统一。
- **弹幕输入**：左下一条下划线输入框，无按钮，回车即发送——弹幕从输入框位置起飞进入屏幕。
- **指令抽屉**：右下“ⓘ”展开为半屏抽屉，内有三栏：被采纳弹幕 / Music Brief / 角色任务 JSON——“编译可见”的证据层全部收在这里，默认隐藏。

### 与 PRD 的映射

Flow 5“逐轨加入”被翻译成最直接的视觉事件；“音乐在循环中生长”这句产品本质第一次有了**字面意义的画面**。90 秒 Demo 的开场 8 秒用 C 方案最抓人。

### 风险

- 工程风险最高：音频-视觉同步、路径动画、canvas 性能都要真功夫；Demo 截止 7-26，需评估是否砍成“环 + 简化音符”。
- “编译过程可见”被收入抽屉，评委可能错过；演示脚本必须包含主动展开抽屉的一步。
- 信息架构极简，制作人裁决、聚类评分这些过程不如 A/B 直观。

## 附：三方案速查对比

| 维度 | A · 指挥台 | B · 演播厅 | C · 环形舞台 |
|---|---|---|---|
| 核心隐喻 | 情报终端 | 直播电视台 | 无限循环乐谱 |
| 观众理解成本 | 中 | **低** | 低 |
| 评委技术说服力 | **高** | 中 | 中 |
| 工程风险 | 低 | 中（像素噪声） | **高**（声画同步） |
| 弹幕融合度 | 叠加层 | **原生** | 原生但弱化 |
| 编译可见性 | **最完整** | 侧栏承载 | 抽屉承载 |
| 记忆点 | 密度与秩序 | 切台噪声 | ∞ 环本身 |
| 与 openDAW 关系 | 时间轴收底作证据层 | 弱化时间轴 | 几乎不展示 |

### 建议

- **主推 B（演播厅）**：弹幕驱动的产品就该用弹幕的原生视觉语言；观众理解成本最低，Demo 叙事最顺；像素噪声系统 2 天内可实现。
- **A 作为结构骨架复用**：B 的侧栏直接采用 A 的右面板信息架构（裁决卡、回执、流水线节点），两者不冲突。
