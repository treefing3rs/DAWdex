## 〇、2026-07-24 后续实施状态

本文后半部分保留了当时发现问题时的原始判断。当前工作区已经完成 P0
音乐语义和执行链的自动化实现：

- Snapshot 可以定位 DAWdex 生成的 Drum、Bass、Keys 轨道及 Region/MIDI 指纹；
- 计划支持 `create`、`add`、`restyle`、`modify`，动作支持按 Track ID
  `upsert/replace`；
- Dubstep → R&B 会原位替换三条角色轨，不再追加三个相同轨道；
- 明确保留 Keys、只改 Drum 时不会改动 Keys/Bass；
- 每次批准执行仍是一个 openDAW Undo 步骤；
- Drum、Bass、Keys 和 Dubstep、R&B 使用不同的乐器参数；
- 已加入 seed、内容指纹和重复 MIDI 防护；
- 回归测试覆盖 Dubstep → R&B → 保留 Keys 只改 Drum，以及逐步 Undo。

后续需求已确定不再由规则编译器生成音符。当前实现从已授权的
`midi/easy` 素材库检索真实 MIDI：

1. `index:midi` 为 194,553 个文件建立本地 SQLite 元数据索引；
2. 索引记录角色、风格标签、BPM、长度、音域、密度和内容指纹；
3. SQL 先做风格/角色筛选、特征排序和内容去重；
4. 模型只在少量真实候选中选择，不直接生成音符；
5. Studio 下载并解析选中的 MIDI，按角色做八度归一化：Bass 保持低音区，
   Keys 保持在 MIDI 48–88，Drum 保留 GM 鼓音高。

当前不需要向量 RAG。目录和音乐属性都是结构化数据，SQLite 的可解释过滤
更适合第一阶段；只有未来需要“像某首参考曲的氛围”一类主观相似度检索时，
再为候选增加 embedding/vector rerank。

自动化验证已通过：Agent Server build、Studio build、7 个相关 Vitest 文件
共 20 个测试、真实 MIDI 下载端点和 `git diff --check`。仍建议在浏览器中进行
一次人工听感验收，重点检查鼓的音色映射、Dubstep/R&B 区分度和 Loop 接缝。

## 一、先说结论

当前版本已经跑通了：

```text
用户输入
→ 全屏弹幕
→ Codex / OpenAI / 本地 Planner 生成计划
→ 用户批准
→ 写入 openDAW 可编辑 MIDI
→ Undo
```

但它仍然是“Agent 控制 openDAW 的技术骨架”，还不是最终规划中的“弹幕驱动 AI 虚拟乐队”。

最关键的缺口不是接入更强的大模型，而是音乐动作协议和执行器过于简单。当前模型无论理解出 Dubstep、R&B 还是其他风格，最后都只能选择四种固定音符模板；它也只能新增轨道，不能修改、替换或删除已有轨道。因此现在不能说大多数产品功能已经完成。

下一步必须优先解决：

1. 风格必须能进入结构化 `MusicBrief` 和执行器；
2. “改成另一种风格”必须替换或变换现有 DAWdex 轨道，不能继续叠加；
3. Drum、Bass、Keys 必须拥有真正不同的风格规则；
4. 同一提示词不能反复创建内容相同的轨道；
5. 之后再做角色舞台、逐轨进入和弹幕裁决。

## 二、最终确定的产品

### 一句话

> DAWdex 是一个内置 openDAW 的弹幕驱动 AI 虚拟乐队：制作人 Agent 把普通人的感受编译成专业音乐任务，并让虚拟乐手在循环播放中逐轨完成一首可编辑的作品。

### 产品不是

- 不是通过 MCP 遥控 Ableton；
- 不是 Prompt-to-Audio 黑盒；
- 不是给 openDAW 外面简单套一个聊天框；
- 不是只做“读取弹幕实时编曲”的单一功能；
- 不是比赛前重做一个完整专业 DAW。

### 核心体验

```text
观众发送自然语言弹幕
→ 制作人选择值得采用的意见
→ 音乐意图编译器生成 MusicBrief
→ 总编曲师拆分 Drum / Bass / Keys 等角色任务
→ 虚拟乐手显示专业决定和通俗解释
→ 轨道在 Loop 边界逐个加入
→ 用户听见自己的意见如何改变音乐
→ 用户继续要求增强、减弱、换风格或重做某一轨
```

黑客松最值得展示的不是“调用了几个 Agent”，而是“人话如何变成结构化音乐意图，再变成用户能立刻听见的作品变化”。

## 五、刚发现的 P0 缺陷

### 复现

1. 在当前工程输入“帮我制作一个 Dubstep”；
2. 得到简单的 6415 和弦进行和根音 Bass，与 Dubstep 没有明显关系；
3. 再输入“帮我改成 R&B 风格”；
4. 系统新增三个轨道；
5. 原来的两个轨道没有修改；
6. 新轨与原轨音乐内容相同或高度相似。

### 期望

- “制作 Dubstep”应至少产生可辨识的 Dubstep Drum、Sub/Wobble Bass 和辅助和声；
- “改成 R&B”属于工程级 `restyle`，默认替换或变换现有 DAWdex 生成轨道；
- 用户明确说“保留某轨”时才保留指定轨道；
- 不应添加与现有轨道音符完全相同的新轨；
- UI 应说明哪些轨被保留、替换、删除或重做。

### 根因一：执行器硬编码了同一个 6415

`DawProjectAdapter.ts` 中的和弦根音偏移固定为：

```ts
0, -4, +3, -2
```

默认根音为 D 时，和弦是：

```text
Dm → B♭ → F → C
```

从 F 大调看正是：

```text
vi → IV → I → V
```

也就是用户听到的 6415。所有风格最终都会经过这一个 `progression`。

### 根因二：模型输出空间里没有“风格”

当前 `CreateInstrumentAction` 只有：

```text
name
pattern: bass | chords | pulse | lead
startBar
bars
rootMidi
velocity
density
```

其中没有：

- genre；
- groove；
- swing；
- drum grammar；
- chord vocabulary；
- bass behavior；
- articulation；
- sound design；
- motif；
- variation seed。

模型即使正确理解 Dubstep，也无法把理解传递给执行器。

### 根因三：只有新增，没有修改

当前动作只有：

```text
set-tempo
create-instrument
```

没有：

```text
replace-track
transform-track
remove-track
keep-track
mute-track
```

所以“改成 R&B”在系统语义里只能退化为“再创建一些轨道”。

### 根因四：项目快照看不到音乐内容

当前 Snapshot 只返回：

```text
name
trackCount
regionCount
```

模型看不到：

- 稳定的 Track ID；
- 该轨是 Drum、Bass 还是 Keys；
- Region 的位置和长度；
- 实际 MIDI 音符；
- 当前调性、和弦和 Groove；
- 哪些轨由 DAWdex 生成；
- 上一次使用的 Style、Seed 和素材。

因此模型既不能定位旧轨，也不能判断新计划是否重复。

### 根因五：生成是确定性的

`compilePattern` 没有 Seed、素材选择或变体。相同的：

```text
pattern + bars + rootMidi + density
```

必然生成相同音符。所有轨道又统一使用 `InstrumentFactories.Vaporisateur`，听感差异进一步缩小。

### 判断

这是动作协议和音乐执行层的结构性问题，不是单纯的 Prompt 问题。只修改 `PRODUCER_INSTRUCTIONS`，最多改变轨道名称和参数，无法产生真正不同的 Dubstep 或 R&B。

## 七、建议冻结的最小音乐协议

不要让模型直接生成任意音符或函数名。下一版可以先用有限的 `upsert-role-track`：

```ts
type MusicRole = "drums" | "bass" | "keys"
type SupportedStyle = "dubstep" | "rnb"

type MusicBrief = {
    readonly intent: "create" | "add" | "restyle" | "modify" | "remove"
    readonly style: SupportedStyle
    readonly bpm: number
    readonly key: string
    readonly bars: 4 | 8
    readonly energy: number
    readonly swing: number
    readonly preserveTrackIds: ReadonlyArray<string>
    readonly roleTasks: ReadonlyArray<RoleTask>
}

type UpsertRoleTrackAction = {
    readonly type: "upsert-role-track"
    readonly mode: "create" | "replace"
    readonly targetTrackId?: string
    readonly role: MusicRole
    readonly style: SupportedStyle
    readonly bars: 4 | 8
    readonly rootMidi: number
    readonly seed: number
    readonly density: number
    readonly energy: number
}
```

这个协议的重点是：

- 模型负责把用户语言编译成有限参数；
- 程序负责根据 Style Profile 生成或检索音乐；
- `targetTrackId` 让“改成”具有真实编辑语义；
- `seed` 让生成可复现但不永远相同；
- 同一个角色只保留一条当前主轨，避免重复堆叠。

## 八、两个风格的最小可听标准

### Dubstep MVP

- 140 BPM，听感可按 70 BPM Half-time；
- 小调；
- Snare/Clap 重点落在每小节第三拍；
- Kick 不使用普通四拍踩满；
- Sub Bass 与节奏型 Bass 有切分和留白；
- 和弦只做稀疏氛围或 Stab，不以 6415 长和弦作为主体；
- 至少 Drum、Bass、Keys 三个角色听感不同；
- 如果暂时没有 Wobble 自动化，也必须先通过节奏和音域表现 Dubstep。

### R&B MVP

- 70–95 BPM；
- 有 Swing 或轻微 Timing 偏移；
- 7th/9th 和弦或更丰富的 Voicing；
- Bass 与 Kick 互补，不只打整齐根音；
- Drum 更松弛，有力度变化；
- Keys 保留空间，避免所有音符完全量化和同力度；
- 从 Dubstep Restyle 时替换原来的三条 DAWdex 角色轨。

## 九、建议的实现顺序

### Step 1：先改协议和 Snapshot

文件：

```text
opendaw/packages/app/studio/src/agent/AgentProtocol.ts
opendaw/packages/server/dawdex-agent/src/MusicPlan.ts
opendaw/packages/app/studio/src/agent/AgentClient.ts
opendaw/packages/app/studio/src/agent/DawProjectAdapter.ts
```

完成标准：

- 请求可以区分 create/add/restyle/modify；
- 每条已有乐器轨有稳定 ID；
- 可以识别 DAWdex 的 drums/bass/keys；
- Actions 可以指向一个旧轨。

### Step 2：实现替换语义

在 `DawProjectAdapter` 中增加：

```text
find generated role track
→ replace its Region/notes，或安全删除后重建
→ verify
→ keep the entire plan as one undo step
```

如果 openDAW 删除/清空 Note Region 的 API 暂时难以定位，黑客松安全方案可以：

1. 按 Track ID 找到旧的 DAWdex 轨；
2. 在同一个 `editing.modify` 中删除旧轨并创建新轨；
3. 保留用户轨和明确要求保留的轨；
4. 失败时不修改工程。

### Step 3：做 Style Profile，而不是继续堆 Prompt

建议新增：

```text
opendaw/packages/app/studio/src/agent/music/StyleProfiles.ts
opendaw/packages/app/studio/src/agent/music/PatternCompiler.ts
opendaw/packages/app/studio/src/agent/music/QualityGate.ts
```

将当前唯一的 `compilePattern` 拆成：

```text
compileDubstepDrums
compileDubstepBass
compileDubstepKeys
compileRnbDrums
compileRnbBass
compileRnbKeys
```

第一版可以是规则生成，不必等 MIDI 素材库。

### Step 4：建立防重复与回归测试

至少测试：

1. Dubstep 不再输出固定 6415 主体；
2. Dubstep 有 drums/bass/keys；
3. Restyle R&B 使用 replace 而不是追加三个重复角色；
4. R&B 和 Dubstep 的 MIDI 指纹不同；
5. 相同 Seed 结果相同；
6. 不同 Seed 产生受约束的变体；
7. 明确保留的 Track ID 不被替换；
8. 一次 Undo 恢复 Restyle 前工程。

可以用排序后的：

```text
pitch + position + duration + velocity
```

计算 MIDI 指纹，阻止完全重复的候选进入工程。

### Step 5：最后接角色 UI 和逐轨舞台

文件：

```text
opendaw/packages/app/studio/src/agent/AgentOverlay.tsx
opendaw/packages/app/studio/src/agent/AgentOverlay.sass
```

UI 不解析模型自由文本，只消费：

```text
MusicBrief
RoleTask
RolePlaybackState
MusicOperation receipt
```

## 十四、下一次验收场景

下一次不要只验证“创建了几条轨道”，必须听和检查实际 MIDI。

### 场景 A：从空工程创建

输入：

> 帮我制作一个 Dubstep，四小节，要有压迫感。

必须满足：

- 返回 Dubstep MusicBrief；
- 创建 Drum、Bass、Keys；
- 不使用当前固定 6415 长和弦作为作品主体；
- 三轨音符指纹不同；
- 听感能辨认出 Half-time 和低频主导；
- 可以 Undo。

### 场景 B：整曲换风格

继续输入：

> 帮我改成 R&B 风格。

必须满足：

- 意图识别为 `restyle`；
- 指向并替换现有 DAWdex Drum/Bass/Keys；
- 轨道总数不会无意义地从 3 变成 6；
- 和弦、Groove、Bass 至少两项发生真实改变；
- R&B 与 Dubstep 的 MIDI 指纹不同；
- 原工程可以一次 Undo 恢复。

### 场景 C：局部修改

继续输入：

> 保留和弦，只把鼓变得更松一点。

必须满足：

- Keys 的 Track ID 和 MIDI 指纹不变；
- 只修改 Drum；
- UI 明确显示“Keys 保留、Drum 重做”。
