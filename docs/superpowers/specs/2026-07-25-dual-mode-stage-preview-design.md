# DAWdex 双形态与工作台舞台预览设计

日期：2026-07-25
状态：已获产品方向确认，等待书面复核

## 1. 背景

DAWdex 当前有两个已实现但入口表达不够准确的使用形态：

1. **产品形态**：完整 DAWdex 演播厅，包括舞台、房间、弹幕、输入、干预、审批和证据。
2. **DAW 形态**：完整 openDAW 工作台，供用户直接编辑底层工程。

现有工作台形态把 DAWdex 顶栏缩成右缘侧拉条。这个入口只表达“把覆盖层叫回来”，没有让用户在 openDAW 中持续看到 DAWdex 产品，也与设备区现有的 ShaderToy 预览位形成重复的视觉焦点。

本设计把设备区原 ShaderToy 预览位改成 DAWdex 演播厅的实时缩略窗。缩略窗既是产品状态预览，也是从 DAW 形态返回产品形态的主要可见入口。

## 2. 决策

采用明确的双形态导航：

```text
DAWdex 产品形态
  └─ 点击“工作台” ──> openDAW 工作台形态

openDAW 工作台形态
  └─ 点击演播厅缩略窗 ──> DAWdex 产品形态
```

两个形态不是两个应用，也不创建第二套 Agent、工程或事件桥。它们共享同一个 openDAW 工程、`RealUiEventBridge`、舞台状态和房间状态。

工作台形态不再显示右缘 DAWDEX 侧拉条。`Esc` 和 `?workbench=1` 保留为键盘与深链能力，但演播厅缩略窗是工作台中唯一的常驻可见返回入口。

## 3. 目标

- 在产品形态与 DAW 形态之间建立一眼可懂的双向入口。
- 在 openDAW 工作台中持续显示当前 DAWdex 演播厅，而不是装饰性或预录替身。
- 切换形态时保留当前房间、角色、走带、弹幕和 Agent 工作状态。
- 让 openDAW 工作区保持完整可操作，不再被 DAWdex 底栏或侧拉条占位。
- 保持单一事件来源，避免重复同步、双重动画或状态漂移。

## 4. 非目标

- 不把完整产品外壳缩小塞进设备面板。
- 不在缩略窗中提供弹幕输入、频道切换、审批、干预或证据抽屉。
- 不创建 iframe、第二个 `AgentOverlay`、第二个 `RealUiEventBridge` 或第二套媒体音频。
- 不删除 openDAW 的 ShaderToy 引擎、编辑器或独立工作区能力；只替换 DAWdex 产品构建中设备面板的预览槽内容。
- 不改变 MIDI 检索、音乐计划、执行、Undo 或 Provider 链路。

## 5. 方案比较

### 方案 A：共享舞台状态 + 两种舞台表面（采用）

把舞台呈现状态从 `AgentOverlay` 的局部 DOM 操作中抽出为共享会话状态。完整舞台与缩略舞台消费同一份状态，但各自按尺寸和交互边界渲染。

优点：

- 状态来源唯一，符合现有真实性闸门；
- 缩略窗可以真实跟随房间、角色、走带和弹幕；
- 完整版与缩略版的视觉职责清楚；
- 后续新增歌曲段落、房间或角色时只扩展一份状态协议。

代价：

- 需要从目前较大的 `AgentOverlay.tsx` 中提取舞台状态与舞台表面；
- 需要为两个表面的同步补充测试。

### 方案 B：移动现有舞台 DOM

在形态切换时把现有舞台节点从产品外壳移动到设备面板预览槽。

优点是改动较少且画面完全相同；缺点是节点跨组件移动会破坏样式作用域、生命周期和事件订阅，openDAW 面板重排时也容易失效。因此不采用。

### 方案 C：静态图片或预录视频

在 ShaderToy 位置播放一段演播厅视频，点击后打开产品形态。

优点是实现最快；缺点是画面不代表当前工程、房间和角色状态，会破坏“没有真实发声就不表演”的产品契约。因此不采用。

## 6. 架构

### 6.1 共享会话

增加一个以当前 `StudioService` 为键的 DAWdex UI 会话。建议使用 `WeakMap<StudioService, DawdexUiSession>` 获取同一页面内唯一会话，避免给 openDAW 核心服务增加 DAWdex 专用字段。

`DawdexUiSession` 至少负责：

- `viewMode`: `"product" | "workbench"`；
- 当前房间；
- Transport/REC 状态；
- 各角色状态与是否真实可听；
- 当前可显示弹幕；
- 最近事件摘要；
- 形态切换方法。

`AgentOverlay` 继续拥有唯一的 `AgentClient`、`DawProjectAdapter` 和 `RealUiEventBridge`。结构化 `UiEvent` 先更新 `DawdexUiSession`，舞台表面再从会话状态渲染。

### 6.2 舞台表面

提取可复用的舞台表面，支持两个明确变体：

- `full`：产品形态中的完整舞台，保留物件热点、频道、弹幕、REC、Transport 和角色表现；
- `preview`：工作台中的只读缩略舞台，只显示当前房间、角色、REC/Transport 和有限弹幕，不渲染热点、输入、频道按钮、审批或抽屉。

两个变体共享房间素材、角色素材、状态映射和真实性规则。`preview` 不是把完整外壳做 CSS 缩放，而是针对小尺寸重新取舍信息。

### 6.3 工作台预览

在 `DevicePanel.tsx` 中，用 DAWdex 工作台预览组件替换当前 `ShadertoyPreview` 槽位。

预览组件要求：

- 使用现有面板槽的可用高度，保持 16:9；
- 视频始终静音，不创建额外音频输出；
- 整个预览是一个可聚焦的按钮；
- 鼠标点击、`Enter` 或 `Space` 切换到产品形态；
- `aria-label` 明确为“打开 DAWdex 演播厅”；
- Hover/Focus 只显示克制的进入提示，不覆盖主要画面；
- openDAW 没有活动设备时仍保留入口，不依赖 ShaderToy Box 是否存在。

ShaderToy 的编辑器、独立工作区、渲染器和导出能力保持原样；只有设备面板右侧的 DAWdex 产品槽位改变。

### 6.4 形态控制

形态切换由 `DawdexUiSession.viewMode` 统一驱动：

- 产品形态点击“工作台”：设为 `workbench`；
- 工作台点击缩略窗：设为 `product`；
- `Esc`：在输入框未聚焦、没有更高优先级面板需要关闭时往返；
- `?workbench=1`：初始设为 `workbench`；
- 投屏模式仍与工作台形态互斥。

进入工作台形态后：

- 产品外壳、输入、抽屉和进棚过场不显示；
- `AgentOverlay` 根节点不拦截 openDAW Pointer Event；
- 现有右缘侧拉条不显示；
- 事件桥、规划状态和走带同步继续运行；
- 设备面板缩略窗成为常驻可见入口。

## 7. 数据流

```text
openDAW 工程 / Agent 结果
          │
          ▼
唯一 RealUiEventBridge
          │
          ▼
DawdexUiSession
    ├── viewMode
    ├── room / transport / roles
    ├── danmaku / latest event
    └── truthful audible state
          │
          ├── product ──> 完整演播厅表面
          └── workbench ──> 设备面板缩略表面
```

形态切换只改变呈现位置与交互密度，不改变工程、Agent 请求或音乐状态。

## 8. 视觉与交互

### 产品形态

- 保留现有完整演播厅、键盘甲板、输入、干预和证据抽屉。
- “工作台”按钮继续作为进入 openDAW 的显式入口。

### DAW 形态

- openDAW 占据完整主界面。
- 设备区右下角原 ShaderToy 预览位显示当前演播厅。
- 缩略窗保留房间画面、当前在场角色、REC/暂停和最少量弹幕。
- 不缩放显示完整 DAWdex 外壳，不显示无法在小尺寸中可靠操作的控件。
- 缩略窗 Hover/Focus 时出现“打开 DAWdex 演播厅”提示和轻微边框反馈。

### 响应式

- 预览优先保持 16:9，空间不足时 letterbox，不裁掉关键角色区域。
- 低于可读阈值时隐藏文字，只保留画面、REC 点和进入提示。
- `prefers-reduced-motion` 下停用非必要预览动效，但保留真实状态变化。

## 9. 生命周期与性能

- 页面中只允许一个 `AgentClient`、一个 `DawProjectAdapter` 和一个 `RealUiEventBridge`。
- 完整舞台与缩略舞台不得同时解码两套有声媒体；所有房间视频静音。
- 不可见表面暂停非必要的 DOM 动画和视频绘制，状态订阅继续保留。
- 切换回来时从共享会话立即渲染最新状态，不重新播放进棚过场。
- 组件卸载时注销 Resize、键盘、媒体和会话订阅。

## 10. 错误与降级

- 房间视频加载失败时使用对应 poster/静态房间图。
- 缩略窗无法取得会话状态时显示演播大厅静态 poster 与“打开 DAWdex”入口，不能阻断 openDAW。
- WebGL/ShaderToy 是否可用不再影响 DAWdex 预览。
- Agent 或服务器不可用时，预览仍显示本地舞台状态及真实暂停/回退状态。

## 11. 验证

### 自动化

- `DawdexUiSession` 的产品/工作台切换与互斥规则单元测试；
- 同一 `UiEvent` 同步更新完整表面和缩略表面的呈现测试；
- 工作台形态隐藏右缘侧拉条、显示预览且不拦截 openDAW 的 DOM 测试；
- 点击、`Enter`、`Space` 和 `Esc` 的导航测试；
- 验证页面中只创建一个 `RealUiEventBridge`；
- 视频失败时静态图降级测试；
- Studio 与 Agent Server 的既有 build/test 全量检查；
- `git diff --check`。

### 浏览器

在 `localhost:7100/create` 验证：

1. 产品形态点击“工作台”后，openDAW 可完整操作；
2. 右缘侧拉条消失；
3. 原 ShaderToy 位置显示当前演播厅缩略窗；
4. 播放/暂停、房间和角色状态在缩略窗中更新；
5. 点击或键盘激活缩略窗返回产品形态；
6. 往返后工程、房间、角色和审批状态不丢失；
7. 不同设备面板高度与窗口尺寸下无溢出或遮挡；
8. 浏览器控制台无新增错误。

## 12. 验收标准

- 用户可以明确识别产品形态与 DAW 形态。
- 两种形态各有一个清晰的主入口：产品中的“工作台”和 DAW 中的演播厅缩略窗。
- 工作台中没有重复的 DAWDEX 底栏或右缘侧拉入口。
- 缩略窗显示的房间、播放和角色状态与完整演播厅一致。
- 缩略窗不包含输入、审批、干预或证据交互。
- openDAW 的设备编辑、时间线、混音和键盘操作不被遮挡。
- 切换形态不重新创建 Agent/事件桥，不丢失状态，也不触发新的音乐操作。
- ShaderToy 的非设备面板功能没有被删除或破坏。
